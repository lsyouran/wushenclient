# 00 · 总纲与文档索引

> **本册是 `docs/` 的唯一入口。** 各册的状态、职责、编号体系、维护纪律都在这里；
> 具体内容一律**留在各册**，本册只给链接 —— 复制一份到索引里，就必然出现两份会逐渐分家的事实。
> 跨册引用统一写作「**N 册 §x**」（例：26 册 §11.2），不写"见另一份文档"。

---

## 1. 项目一句话

用 TypeScript 重写 MUD 服务端（`D:/ts-mud/newmud`），研究对象是 `D:/ts-mud/wushen` 的 JS 源码。
不是"照抄一遍"，而是**先解剖 wushen 哪里会翻车，再用 TS 的类型与闸门让那类错误在结构上无法发生**。
因此本项目的文档有一半篇幅在讲"**不抄什么、为什么**"。

## 4. 维护纪律（★ 防止"文档越写越乱"）

1. **发现问题 → 更新原册，不另起一册。**
   第二轮审查曾一度单独成册，结果同一件事（网络层前置项）在 26 册 §4 与新册里各写一半，
   读者必须两份都读才知道全貌 —— 已合并回 **26 册 §11**。
   **判据**：如果新文档里有"续 / 补充 / 更正"某册的内容，它就应该并进那一册。

2. **索引只放链接，不放内容。** 内容一旦复制，两份就会分家，而没有任何闸门能发现（24 册铁律 7）。

3. **状态写在标题行第一句。** 文件名带"（提案）"而内容已落地，是最典型的**文档假绿**（FG-9/FG-10 同族）。
   状态变了就改标题行与文件名，不要靠读者自己判断。

4. **每条结论都要有"怎么证明"**：实测输出 / 断言 / 闸门编号三选一。读码推断的必须标注「读码确认」。

5. **SKIP 必须显式写出**。闸门没跑起来 ≠ 通过（24 册铁律 3）。26 册与闸门汇总里都要能看到 SKIP 项。

6. **★ 三方对账：文档 ↔ 代码 ↔ wushen 原作**（缺一角就会漏一类问题）：
   - 只看文档不看代码 → 抓不到"文档没写的事"（文档假绿）；
   - 只看代码不看文档 → 抓不到"实现悄悄偏离了设计意图"，且偏离会被当成"本来就这样"；
   - **两边都不看 wushen** → 抓不到"文档与实现**一致地一起偏离原作**" —— 这类偏差往往到移植内容时才炸。
     R7（0 级技能仍贡献属性）就是这么找出来的：文档与实现都做到了"记账式幂等"，
     只有把 wushen `if (!lv) return` 那两行摆到旁边才看得出还少一条。
   对账结论记在 **26 册 §12**，每条标注 wushen 的 `文件:行号` 便于复查。

## 7. 版本控制（2026-10-15 引入）

本仓库 `D:/ts-mud` 于 **2026-10-15** 起纳入 git（初始提交 **`4293b5c`**，分支 `main`）。
此前项目**完全没有版本控制** —— 核实报告 `_verify-问题记录核实-2026-10-15.md` 曾把它列为结构性缺口，**现已消解**。
本条只留"会踩的"；批次记录见 **26 册 §38**。

| 项 | 约定 |
|---|---|
| 仓库根 | `D:/ts-mud`（**一个库**覆盖 `newmud/` + `docs/` + `wushen/` + 根报告） |
| 入库 | `newmud/`（源码/测试/工具/内容）· `docs/` · `wushen/` 原版源码 · 根 `_*.md` 报告 · `.workbuddy/memory/`（决策日志） |
| 不入库 | 依赖 `node_modules/` · 构建 `dist/` · 运行时数据 / 日志 · 变异夹具 `__mut*` / `*.mutbak` · 一次性证据 `_bench-*` / `_shots-*` / `_tmp-trash/` / `_deprecated-*` · `_*.log` · 压缩包 `*.7z` |
| 行尾 | **`.gitattributes` 设 `* -text`，全程禁止 EOL 转换** —— 理由见 26 册 §36.7（CRLF 事故） |
| 身份 | 仓库**本地** `user.name=Administrator` / `user.email=admin@ts-mud.local`（**不动全局配置**） |

★ **两条会踩的**：
1. **`.gitignore` 不支持行内注释** —— `#` 只有**行首**才是注释；写在规则后面会被当成**规则的一部分**而
   **静默失效**（本批实际踩到，五类一次性证据全漏进暂存区；见 26 册 §38.2）。
2. 规则改对后，**已在索引里的文件不受 `.gitignore` 影响** —— 必须先去掉再重加（`git rm -r --cached`
   或直接删 `.git/index` 重建，无提交时后者最干净）。
