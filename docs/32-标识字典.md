# 32 · 标识字典（★ 查名字先看这一册）

> **这本册子只干一件事：当你看到一个字符串标识、不知道它是什么意思 / 该写哪个 / 谁在守它时，
> 能在这一页里查到。** 规范条文不在这里 —— 命名法在 24 册，属性与派生数值在 29 册，
> 技能在 27 册，审查与批次在 26 册。
>
> 立足点：**2026-10-18 §66 之后，全栈只有一套英文 snake_case 数据键**
> （代码 / 内容层 `prop:{}` / 协议帧 / 存档同一个名字）。wushen 的拼音键
> （`gj`/`fy`/`ds`…）从此只出现在"旧键"那一列与历史对照表里。
>
> **单一来源**：本册的每一张表都能在代码里找到出处（每节标了 `来源：` 行）。
> 表与代码不一致时，**以代码为准并回来改本册** —— 这是 26 册 §5「注释/文档也是断言」。

## 32.0 三条查法（先看这里，别通读）

| 你想知道什么 | 去哪儿 |
|---|---|

| 面板/帧/频道/错误码的名字 | §32.8 / §32.9 |
| 我要新建一个 id 或目录，会不会撞保留字 | §32.10 |
| 我想新增一个标识，要动哪几处 | §32.12 |

**★★ 一句话记住四个命名空间**：**属性键**（`attack`/`max_hp`）、**技能 id**（`dodge`/`sword`）、
**装配槽**（`force`/`sword`）、**方向/频道/帧**（`north`/`chat`/`room`）——
它们**互不共享词语**，共享就是 bug（G3.G 守这一条）。

### 32.2.3 ★★ 三个"同名不同物"（写公式前必须看清 receiver）

| 加成侧（`props.*`） | 值侧 | 区别 |
|---|---|---|
| `props.str` / `con` / `dex` / `int` | `innateStats.str`（键 `innate_str`） | 前者是**加成池**，后者是**建号时定下的先天值** |
| `props.max_hp` | `derived.maxHp` | 前者是加成，后者是算出来的上限 |
| `props.max_mp` / `limit_mp` | `derived` 里的内力 | 前者是加成/加数，后者是池子 |

★ §66 删掉 `PROP` 别名层之后，这三条**只剩 receiver 能区分**（wushen 也是这么做的）。
旧写法 `PROP.strengthBonus` / `PROP.maxHpBonus` 的"名字上岔开"已经不存在了 ——
**别再想着用后缀把两者分开**（29 册 §29.11.1 条③）。

## 32.3 派生族规则（`ModProp`）

> `来源：shared/constants.ts` 的 `ModProp` 类型 + `isPropKey()` 守卫。

核心键 `C` 自动派生出 5 族，**名字由 C 机械生成，不许单独起名**：

| 形态 | 语义 | 例（C = `attack`） |
|---|---|---|
| `<C>_per` | 百分比加成 | `attack_per` |
| `diff_<C>` | 减免 / 抵抗 | `diff_attack` |
| `diff_<C>_per` | 减免百分比 | `diff_attack_per` |
| `add_<C>` | 追加 | `add_attack` |
| `add_<C>_per` | 追加百分比 | `add_attack_per` |

★ 类型上合法（`PropKey`）**不等于**有引擎消费者：`isPropKey('add_attack')` 为 `true`，
但只有写进 `formula.ts` 的那几个才真的被读。**"类型合法"是最低门槛，不是承诺。**
★ 守卫按 **6 族各自独立判定**，不做"一次剥前缀+后缀"—— 那样会多剥一层，
误拒 `add_crit_per`（= `add_` + `crit_per`）、`diff_damage_per_per` 这类合法键
（历史缺陷，`tests/g3-constants.test.ts` 钉住）。

## 32.5 旧拼音键 → 新键（移植 wushen 内容时用这张）

> `来源：shared/constants.ts` 的 `LEGACY_PINYIN_KEYS`（**冻结，永不扩充**）。
> 唯一消费者是闸门 **G3.A** 的报错文案：内容层写 `gj` 会当场说"请改用 `attack`"。
> ★ 它**不是**第二份键表：类型是 `Record<string, CoreProp>`，再改一次名会编译失败。

**关键替换（背这 10 条就够抄 90% 的内容）**

| 旧 | 新 | 中文 |
|---|---|---|
| `gj` / `gj_per` | `attack` / `attack_per` | 攻击 |
| `fy` / `fy_per` | `defense` / `defense_per` | 防御 |
| `ds` | `evasion` | 躲闪 |
| `zj` | `deflect` | 招架 |
| `mz` | `hit` | 命中 |
| `bj_per` | `crit` | 暴击 |
| `sh` | `damage` | 伤害 |
| `gjsd` | `attack_speed` | 攻速 |
| `diff_sh` / `diff_sh_per` | `diff_damage` / `diff_damage_per` | 减伤（固定 / 百分比） |
| `per` | `appearance` | 容貌 |

**全量规则**：`docs/29` §29.11.2 的甲表（18 词干，整族跟随）+ 乙表（38 独立键）。
**词干级心法**：先把词干换掉（`gj→attack`、`sh→damage`），派生形态自动跟着走，别逐条改。

★ **四种最容易抄错**：
1. `dazuo`（打坐**效率**）→ `meditation`；但**指令 id** `dazuo`（打坐）**不改**。
2. `score`（副本分数）→ `instance_score`；但**面板名** `dialog:'score'`**不改**。
3. `busy`（忙乱时间）→ `busy_time`；但 `allow_busy` 闸门、`CommandActor.busy`**不改**。
4. `con`/`dex`/`int`/`str` 本身**没改**，但 `con1`/`dex1`/`int1`/`str1` 改成了
   `innate_*` —— 抄"先天四维"时最容易漏。

## 32.6 技能相关的四个词（★ 最容易混）

| 词 | 是什么 | 取值 | 来源 |
|---|---|---|---|
| **kind** | 内容对象的种类 | **见 §32.13.6**（8 个，生成块） | `ids.ts#KINDS` |
| **技能内容 id** | 具体哪门武功 | **见 §32.6.1 的全表**（由 `npm run ids` 从 `world/skill/` 生成，**不手抄**） | 内容文件 `defineSkill(...)` |

`WEAPON_TYPE`（7 个，含 `unarmed`）是武器系槽。两者并集 = `ENABLE_SLOTS`（11 个），
**集合等价由测试机检，不靠人眼**。

★ 已落地的基本武学 6 门：`base/{force,dodge,parry,unarmed,sword,blade}`（§65）。
`base/bite` 是 wushen 有、本项目**还没做**的第 7 个槽。

| `admin/addxp` | 加经验 / 潜能（**测试期**，见下） | `world/command/admin/` |

★ **`admin/addxp` 为什么不是 `train/` 或 `info/`**：它是**运营/调试面**的写入口，不是游戏动作。
它直接调 `CommandActor.grantExp()`（`Character.addExp` 的转发），等于**绕过打怪直接改成长账** ——
所以单独一个 `admin/` 目录，将来 GM 工具（发钱、刷物品、传送）都归这里，一眼能看出
"这个目录里的东西上线前要被授权挡住"。

★★ **它现在的门是 `allow_level: 0`，不是 `9`** —— 这是**故意的**，不是漏写：
`userLevel` 只有构造器那句 `this.userLevel = init.userLevel ?? 0`（`character.ts`），
**没有任何生产代码给 `init` 传过非 0 值**（扫描面：`newmud/server/**` 与 `newmud/src/**` 里
`userLevel` 的写入点只有这一处；传非 0 的只有 `tests/engine-command.test.ts`）。
⇒ 写成 `allow_level: 9` 会让这条指令**永远不可用**（26 册 L8 病型：声明存在、消费为零）。
所以改成 `allow_level: 0`（谁都能进）＋ `run()` 内判 `me.userLevel >= 9` 才免"测试指令"横幅。
**接上 GM 授权那天，两处要一起改回**（指令声明 + 那条横幅）。

★ **为什么是 `train/` 而不是 `skill/`**：`skill` 是保留 area（`RESERVED_AREAS` 含全部 `KINDS`），
`defineCommand('skill/learn', …)` 会在 `asWorldId` 那一关抛 `IdError`；G5 又要求"路径推出的 id =
define 里写的 id"。`practice` 先踩过这个坑，`learn` 跟着落在 `train/`。

★★ **这一行原来写错了，原因值得记**：我最初是用
`grep -oP "defineCommand\('\K[^']+"` 抓的 id 清单，结果把 `train/learn.ts:32` **注释里**那句
"`defineCommand('skill/learn', …)` 会抛 `IdError`" 也抓了出来 ⇒ 凭空多出一个不存在的目录。
**grep 会命中注释**；核清单时要 `grep -v '^\s*\*'`，或者干脆以 `ls` 的目录为准。

★ **`dazuo`（打坐）是"房间派生的动作"**，不是本表里的全局指令 —— 它出现在
`engine-command` / `engine-world` 测试里作为 action id，与属性键 `meditation` 无关。

## 32.8 协议帧（`packet type`）

> `来源：shared/protocol.ts`。前端**只许 `import type`**（G14），不许 import 运行期值。
>
> ★★ **两个方向是两张表，别混**：`SERVER_PACKET_TYPES`（35，服务端 → 客户端）与
> `CLIENT_PACKET_TYPES`（3，客户端 → 服务端）。**`login` 两边都有**，但是两个不同的 interface。
> 完整名单见 §32.13 的 `packet` / `clientPacket` 两个生成块（G18 守）。

**服务端帧（`SERVER_PACKET_TYPES`，35 个）**

| 分类 | `type` 取值 |
|---|---|
| 登录 / 角色 | `roles` · `login` · `loginerror` · `regist` · `deleterole` |
| 房间 / 地图 | `room` · `exits` · `items` · `itemadd` · `itemremove` · `item` · `map` · `updatemap` |
| 动作 | `actions` · `addAction` · `removeAction` · `cmds` |
| 面板 | `dialog` · `setting` · `pay` · `emote` · `perform` · `dispfm` |
| 战斗 / 状态 | `combat` · `sc` · `status` · `die` · `state` |
| **绝招 / 对象变更** | `disobj` · `changepfm` · `clearDistime` |
| 播报 / 其他 | `msg` · `warn` · `cross` · `levelup` |

**客户端帧（`CLIENT_PACKET_TYPES`，3 个）**

| `type` | 说明 |
|---|---|
| `command` | 玩家输入一条指令 |
| `login` | 登录 / 注册（与同名的服务端帧**不是**一个 interface） |
| `ping` | 心跳 |

★★ **这张表原来错了四处，原因值得记**（2026-10-19 加 G18 时实测）：
它把"播报 / 其他"那一行写成了 `msg` · `warn` · `cross` · `levelup` · **`command`** · **`ping`** ——
后两个**只存在于 `CLIENT_PACKET_TYPES`**，被当成服务端帧抄了进来；
同时**漏掉** `disobj` / `changepfm` / `clearDistime`（它们夹在 `dispfm` 与 `msg` 之间，肉眼扫表时跳过了）。
⇒ 一份"看起来完整、实际既多又少"的名单，**比没有名单更危险**：读者会用它去判断"这个帧存不存在"。
这就是 §32.13 要把其余八组也做成生成块的原因（名单交给机器，人只维护解释）。

★ **`addAction` / `removeAction` 是 `ActionChangePacket` 的两个取值**（同一个 interface，
按"增/删一条动作"分两个 type）—— 它**不是** `actionchange`。写错这个名字协议会判为未知帧。

**`dialog` 帧的两个子词表**

| 词 | 取值 | 来源 |
|---|---|---|
| 面板名 | `pack` `pack2` `list` `shop` `score` `skills` `master` `stats` `tasks` `events` `jh` `trade` `paimai` `party` `team` `relation` `message` `channel` `map` `setting` `keys` `extend` | `DIALOG_NAMES` |
| 控制字段 | `close` · `refresh` · `clear` · `remove` | `DIALOG_CONTROL_FIELDS` |

**频道（`msg.ch`）**：`chat` · `tm` · `fam` · `pty` · `es` · `rumor` · `tell` · `sys`
★ **没有 `say` / `emote`** —— 房内说话走 `sendRoom`，`emote` 是**包类型**不是频道
（wushen `msg.ch` 只有 7 种，26 册 §24）。

**状态动作（`status.action`）**：`add` · `remove` · `refresh` · `override` · `clear`

## 32.10 内容 id 与保留字（★ 造目录 / 起 id 前必查）

> `来源：shared/ids.ts` 的 `KINDS` / `RESERVED_AREAS`。

**id 形状**（`ids.ts` 原文，★ **kind 不写进 id**）：

```
id   := <area> ( '/' <segment> )* [ '#' <variant> ]      段数 1~5
```

- `area` 是**唯一允许单段**的 kind（`yz` 就是一个合法 area id）；
- 其余 kind 至少 **2 段**（`yz/road`、`base/force`、`drug/yao#0`）；
- **kind 由 `define*` 函数与所在目录承载**，不出现在字符串里 ——
  磁盘路径恒等于 `world/<kind>/<id>.ts`（`world/skill/base/force.ts` → id `base/force`）。

★ 所以 `item/jian` 这种"把 kind 写进 id"的写法**是错的**；`G5` 会拦。
★ `#变体` 是同一文件派生多个对象（`drug/yao#0` ~ `#3`），照抄 wushen 的 `#` 语法。

**保留字（area 不得占用）**

| 类别 | 取值 |
|---|---|
| 全部 `KINDS` | `room` `area` `npc` `item` `skill` `family` `command` `task` |
| 工程目录 | `shared` `server` `src` `tools` `index` `test` `tests` |

★ **完整名单见 §32.13.8（生成块，G18 守）** —— 本表只是按类别分成两行，方便读。

★★ 因为 `item` / `npc` / `skill` 都是保留字，**`world/item/` 这样的目录能建**（那是 kind 目录，
名字来自 `KINDS`），**但 area 不能叫 `item`** —— 否则 id `item/jian` 里那个 `item`
会同时像"kind"又像"area"，读者与解析器都无法区分。踩过两次 ⇒ 起 id 前先看这张表。
`obj/drop` 这类 id 是安全的（`obj` 只是 `world/command/` 下的普通 area）。

## 32.12 新增一个标识要动哪几处（收工清单）

| 你要加 | 必须动 | 会被谁拦下 |

| 一个**属性键** | ① `PROPERTIES` 加一行（中文名 + 旧键注释）② 若有引擎消费者，在 `formula.ts` 用**字面量**读 | G3.C（引擎键不在允许集）；`tests/g3-constants.test.ts` |

| 一个**错误码** | `error-codes.ts` 的 `ERROR_CODES` 加一条 | 类型 `ErrorCode` |

| 一个**内容层自造属性** | `registerExtProp()` 登记（**不是**改 `PROPERTIES`） | G3.B / G3.D |

★ **改完必跑**（30 册的验证内环）：双 `tsc` → `vitest` → `gate:run-all` → 若动了闸门或测试，
再跑 `gate:mutation`（证明它仍会变红）。

★★ **加了标识之后**：跑 `npm run ids --check`。它核对**九组**里每一组的生成块
（指令 / 技能 / 协议帧**两个方向** / 错误码 / 属性键 / kind / 装配槽 / 保留区），
**九组全部已建块** ⇒ 任何一组漏了都会红，并报"代码有、文档缺"与"文档有、代码无"两侧差异。
修法：`npm run ids --write`（**只重写块内，块外一个字不碰**）。
★ **块外的解释文字仍要人写** —— 生成器只保证"名单不漂"，不保证"说明还对"。
★ 想看全量清单（不写回任何文件）：`npm run ids`。

★ **这条默认值本身就是判据**：`--check` 默认范围是 `BLOCK_GROUPS`（有块的组）。
2026-10-19 §71.7 时只有 `skill` 一组有块，那时若默认八组全查，其余七组会**每次都报"找不到标记块"**，
噪音会淹掉唯一真实的判据。现在九组都有块了，这个默认值就自动扩到了九组 ——
**同一行代码，随着"建块"这个动作逐步收紧**，不需要改判据。
