## 2.2 配置加载（config.js）

```js
// config.js
module.exports = {
    DB: require('./data/sql'),
    init: async function () {
        if (!(this.WEB_PORT > 1000)) throw new Error('缺少环境配置WEB_PORT');
        if (!(this.def_server.port > 1000)) throw new Error('缺少环境配置WS_PORT');
        if (!this.MD5) throw new Error('缺少环境配置md5');
        if (!this.DESIV) throw new Error('缺少环境配置DESIV');
        if (!this.SESSION_SECRET) throw new Error('缺少环境配置SESSION_SECRET');
        await this.DB.connect('database.db');
    },
    WEB_PORT: parseInt(process.env.WEB_PORT),
    CONNECT_LEVEL: 0,          // 服务器状态：0 正常
    MD5: process.env.MD5_PREFIX,
    SESSION_SECRET: process.env.SESSION_SECRET,
    HEARTBEAT: 5000,           // ★ 全局心跳间隔 5 秒
    DESIV: process.env.DESIV ? Buffer.from(process.env.DESIV, 'utf8') : null,
    def_server: { ip:"127.0.0.1", port: parseInt(process.env.WS_PORT), id:100, name:"本地测试", istest:true }
};
```

`.env` 实际值（`wushen/.env`）：

```ini
WEB_PORT=8088
WS_PORT=31300
MD5_PREFIX=12345
SESSION_SECRET=123
DESIV=1234123412341234
```

> ⚠️ `DESIV` 必须是 **16 字节**（AES-128-CBC 的 IV 长度）。`1234123412341234` 恰好 16 字符，符合。改配置时务必保持 16 字节，否则 `createDecipheriv` 直接抛错。

## 2.4 资源加载顺序（★ 决定 extends 机制是否生效）

`os/world.js:286-341 loadResource()` 按**固定顺序**递归 `readdir` 每个目录，对每个 `.js` 调 `BASE.CREATE(basePath, fname)`：

| 序 | 目录 | `__PATH` | 写入的索引 | 依赖 |
|---:|---|---|---|---|
| 1 | `world/extends/` | EXTENDS | 改写各 prototype | **必须最先**，否则补丁被后续覆盖 |
| 2 | `world/cmd/` | COMMAND | `WORLD.COMMANDS` | — |
| 3 | `world/family/` | FAMILY | `FAMILIES` | — |
| 4 | `world/obj/` | OBJ | `WORLD.OBJ_STROE` | — |
| 5 | `world/area/` | AREA | `WORLD.AREAS` | FAMILIES（反填 `family.area`） |
| 6 | `world/skill/` | SKILL | `WORLD.SKILLS` | **依赖 3**（`FAMILIES.NONE` 必须已存在） |
| 7 | `world/map/` | MAP | `WORLD.ROOMS` | **依赖 5**（`getAreaByPath` 查 AREAS） |
| 8 | `world/task/` | TASK | `WORLD.TASKS` / `SYSTEMTASKS` | — |

> **❌ `world/npc/` 不在加载列表**。NPC 是懒加载：`NPC.GET(path)` 发现 `WORLD.NPC_STROE` 没有时才 `BASE.CREATE`（`os/char/npc.js:219`）。
> 同理 `OBJ.CREATE` 也有兜底懒加载（`os/item/obj.js:154`）。

加载时每个文件都会被 `new BASE()` 一次，控制台打印 `资源脚本加载%d`。

## 2.5 全局心跳（os/world.js:167-193）

```js
WORLD.heart_beat = function () {
    WORLD.CONNECT_COUNT = 0;
    // ① 玩家心跳
    for (i in WORLD.USERS) WORLD.USERS[i].heart_beat(dt);
    // ② 扩展钩子
    WORLD.on_heart_beat(dt);
    // ③ 房间心跳（遍历房内非玩家）
    for (i in WORLD.RUN_ROOMS) WORLD.RUN_ROOMS[i].heart_beat(dt);
    // ④ 每 720 次（= 5s × 720 = 60 分钟）全量存档
    if (++WORLD.HEARTBEATCOUNT > 720) WORLD.save();
}
```

| 对象 | 心跳职责 |
|---|---|
| `USER.heart_beat`（`os/char/user.js:503`） | 长状态机推进（打坐/练习/疗伤）；断线超时踢出（有 state 24h / 无 state 1h）；`request_count` 清零 |
| `NPC.heart_beat`（`os/char/npc.js:173`） | 脱战后回血回蓝、随机喊话 |
| `MONSTER.heart_beat`（`os/char/monster.js:84`） | 同上 |
| `ROOM.heart_beat`（`os/room/room.js:472`） | 遍历房内非玩家各自心跳 |

> **战斗不在全局心跳里**。战斗是每角色一条独立的 `setTimeout` 自递归链，详见第 11 册。

## 2.6 停机流程

```js
// world/extends/world.js:45-63
WORLD.close = function () {
    this.status = 5;                          // 拒绝新连接
    // 断开所有 socket
    clearInterval(this.heart_beat_service);
    WORLD.save();                             // 最后全量存档
}
```

存档触发点汇总：

| 触发 | 代码 | 范围 |
|---|---|---|
| 心跳累计 720 次（约 60 分钟） | `os/world.js:183-187` | 全量 `WORLD.save()` |
| 玩家退出 | `os/world.js:194 login_out` → `user.save()` | 单角色 |
| 服务器关闭 | `world/extends/world.js:45` | 全量 |
| GM 命令 / HTTP 接口 | `api/gm.js saveAll` | 全量 |

## 2.8 前端构建（vite.config.js）

```js
export default defineConfig({
  root: './src/',                 // 源码根
  publicDir: false,               // ★ 关闭 public 目录 → fonts/img 必须靠 JS/CSS import
  build: {
    outDir: '../www/',            // 产物由 web.js 静态托管
    emptyOutDir: true,
    rollupOptions: { input: { index: 'index.html' } }   // 单入口
  },
  server: { port: 3333, open: true }
});
```

| 命令 | 作用 |
|---|---|
| `npm run dev` | Vite 开发服务器 `:3333` |
| `npm run build` | 构建到 `www/` |
| `npm run preview` | 预览构建结果 |

> ⚠️ 开发服务器**没有配置 proxy**，但前端 HTTP 请求用相对路径 `/`（`src/utils/util.js:3 ProxyHost = "/"`），而 WebSocket 是**直连 `ws://<ip>:<port>`**。所以 `npm run dev` 时 HTTP 接口会 404，只有 `npm start`（Web 服务在 8088 同源托管）才能完整跑通。

## 2.9 复刻时的启动流程建议

保留的顺序原则：

1. **配置校验先行**（本项目 `config.init()` 抛错式校验，值得保留，避免配错环境静默出错）
2. **引擎 → 补丁层 → 内容层** 三段式加载，内容层内部按依赖排序
3. **全局心跳与业务定时器分离**（本项目已做到，值得保留）
4. 建议改进：
   - 加载顺序改为**显式清单**而非 `readdir` 目录序（当前靠文件系统返回顺序，跨平台风险）
   - `os/` 的隐式 require 依赖网改为显式依赖图
   - 启动阶段输出各阶段耗时与对象计数，便于定位加载失败
