# 21 · 技术债与风险清单

> 本文列出**已通过源码核对确认**的缺陷，按严重度排序。每条给出位置、影响、复刻时的规避建议。

## 21.1 P0 —— 会导致数据破坏或远程代码执行

| # | 位置 | 问题 | 影响 | 规避 |
|---:|---|---|---|---|
| 1 | `src/client.js:169`<br>`src/utils/util.js:126` | 用 `new Function("return "+data)` 解析服务端 JSON（而非 `JSON.parse`） | **远程代码执行**：服务端下发含右值表达式的字符串即可执行任意 JS | 改 `JSON.parse` + try-catch |
| 2 | `os/util/hotload.js:63` | 取 `sandbox.module.exports`，但 `world/` 下 926 文件**零 `module.exports`**，恒为 `{}`；而 `{}` 是 truthy 不走 `if(!exports) return` | **用空对象覆盖** `WORLD.COMMANDS[name]` / `WORLD.SKILLS[name]` / `OBJ_STORE` 条目，指令被打坏 | 删除该模块，统一走 `BASE.UPDATE` |
| 3 | `world/cmd/admin/*` 的 `call` 指令 | `SendCommand("call this.hp=1000000")` 本质是服务器 eval 任意代码 | GM 后台无二次鉴权 → 任意 GM 可执行任意代码 | 改白名单命令集 + 审计日志 |
| 4 | `api/base.js:101-104` | 会话票据明文含 **MD5 密码**（`id%name%pwd%time%level`），180 天有效且 `loginTime` 无任何校验 | Cookie 泄露 = 账号永久泄露 | 票据改为不含密码的随机 token + 服务端 session 存储 + 有效期校验 |

## 21.4 架构级债务（无法用"修 bug"解决）

| # | 问题 | 影响 |
|---:|---|---|
| A | **全局裸变量**（`BASE`/`CHARACTER`/`WORLD`/`FAMILIES` 全在 globalThis），无模块系统 | 无法单元测试隔离、无法 tree-shaking、加载顺序敏感 |
| B | `os/` 加载靠 `readdir` 目录序 + 各文件顶部 `require` 的隐式依赖网 | 跨平台风险、无法静态分析依赖 |
| C | 协议用**手工字符串拼接**，无 schema、无类型 | 字段错配静默失效；改 `JSON.parse` 会全崩（因为有无引号 key 和单引号） |
| D | `extends` 补丁层无冲突检测 | 同名方法被两处覆盖（见 #20） |
| E | 23 个 dialog 无统一生命周期接口 | 6 种钩子组合，新增面板无从参考 |
| F | 任务引擎无进度容器 | 每个任务自己发明一套，用 `set_temp/query_temp` 存 |
| G | 战斗用"每角色一条 setTimeout 自递归链" | 千场战斗 = 千个定时器，无法统一调度/暂停/回放 |

## 21.5 复刻时的"必须做"清单

按落地顺序：

| 阶段 | 事项 |
|---|---|
| **地基** | ① ESM + 显式依赖注入 ② JSON 协议 + TypeScript 类型 ③ 常量表统一 |
| **通信** | ④ `JSON.parse` ⑤ 心跳 + 自动重连 ⑥ Ping/Pong ⑦ 票据不含密码 + 有效期 |
| **引擎** | ⑧ 单继承 ⑨ `OBJ_STORE` 拼对 ⑩ 索引改 Map ⑪ 统一 `recount` ⑫ 战斗改全局 tick |
| **内容** | ⑬ 保留脚本体范式但加 `define*()` 封装 ⑭ 写 `validate_world.js` 静态校验 |
| **前端** | ⑮ Dialog 统一基类 ⑯ CSS 变量主题 ⑰ 真实响应式 ⑱ 删死资源 |
| **运维** | ⑲ GM 命令白名单 ⑳ 存档结构化 ㉑ 加载耗时的可观测性 |
