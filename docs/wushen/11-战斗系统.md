## 11.1 驱动方式（★ 最需要澄清的一点）

| 层次 | 机制 | 代码 |
|---|---|---|
| **全局心跳** | `setInterval(WORLD.heart_beat, 5000)`（`world.js:122`） | 只驱动回血/状态机/断线超时；**战斗不在里面** |
| **战斗回合** | 每角色一条独立的 `setTimeout` 自递归链 | `combat.js:21` 启动，`extends/char/auto_combat.js:56` 续期，周期 = `gjsd`（默认 4000ms，下限 500ms） |

```js
// os/char/combat.js:21（开战时）
this.attack_handler = this.call_out(this.auto_attack, Math.random() * this.gjsd);

// world/extends/char/auto_combat.js:56（每回合末尾）
this.attack_handler = this.call_out(this.auto_attack, this.gjsd);

// os/char/combat.js:117（停战时）
clearTimeout(this.attack_handler);
```

**准确描述**：全局 setInterval 只驱动回血/状态机；战斗是**事件驱动 + 每角色一条定时器链**的混合模型。

> ⚠️ 千场战斗 = 千个定时器，无法统一调度、无法批量暂停。复刻时建议改为"全局 tick + 战斗注册表"。

## 11.2 回合循环（auto_combat.js:7-58）

```
auto_attack()
 ├─ target = query_enemy()          （combat.js:123，顺带清理已死/离场/停战的敌人）
 ├─ hp<=0 → target.end_attack(this) 或 end_fight()
 ├─ !target → end_fight()
 ├─ is_faint → 延后 is_faint ms 重试
 ├─ release_time>0 → 延后到出招结束
 ├─ is_busy
 │    ├─ auto_pfm && busy_pfm → check_pfms(target)（可解忙乱的绝招）
 │    └─ 否则延后 is_busy ms
 └─ 否则
      ├─ check_pfms(target)（auto_combat.js:84）
      │    ├─ auto_skills 为空则 init_pfms()（:134）
      │    ├─ attack_count 节流：random(attack_count)!=0 → 本回合不放招
      │    ├─ 过滤 ban_use / !allow_busy / release_time 未到 / mp 不足
      │    └─ canuser.random() → use_pfm() → 设 release_time / skill.release_time
      └─ 没放招 → do_attack({target, gj:this.gj, mz:this.mz})
 最后：end_attack(target, sh) 为 true → 再排下一次 auto_attack(gjsd)
```

### `damage(sh, from, diff_fy)` 九步减伤

```
① diff_sh_per -= diff_sh_per * diff_fy / 100      （目标被破防）
② fy         -= fy * diff_fy / 100
③ diff_sh_per -= from.diff_fy_per                 （攻击方忽视防御，先扣免伤）
④ fy         -= fy * from.diff_fy_per / 100
⑤ sh         -= sh * diff_sh_per / 100
⑥ ★ sh = sh / (sh + fy) * sh                      ← 核心：防御递减曲线
⑦ sh -= query_prop("diff_sh")
⑧ equipment[1].on_defense                          （衣服特判）
⑨ force_skill.on_damage → parseInt → add_hp(-sh)
```

> 第 ⑥ 步 `sh/(sh+fy)*sh` 是典型的**递减收益曲线**：防御越高边际收益越低，且伤害永远不会归零（除非 `fy` 极大）。这是本项目数值设计里最值得抄的一行。

**另有两条简化入口**：`damage2(sh,from)`（`:250`，跳过防御）、`damage3(sh,from)`（`:266`，纯扣血）。`from_attack`（`:180`）给陷阱等非回合流程用。

## 11.6 死亡与掉落（os/char/npc.js:123-152）

```js
NPC.prototype.die = function (killer) {
    if (this.on_die && this.on_die(killer) == false) { this.hp = 1; return false; }  // ★ 免死
    this.hp = 0;
    this.clear_status();
    this.send_room(DIE_MSG.random());
    var corpse = new CORPSE();
    corpse.init(this, this.environment.is_fb());        // ★ 掉落物进尸体
    this.environment.item_changed(corpse, true);
    this.environment.item_changed(this, false);
    if (isinfb && this.score) killer.add_fbscore(this.score);
    if (!isinfb && !this.no_refresh && !this.master) {
        this.call_out(this.relive, this.on_master ? 60000 : 300000);   // 5 分钟重生
    }
    this.on_died && this.on_died(killer, corpse);
    WORLD.auto_get(killer, corpse, this);
    if (killer.attack_skill?.on_enemy_die) killer.attack_skill.on_enemy_die(killer, this);
}
```

玩家死亡（`user.js:392`）同样生成尸体，并发 `{type:"die", commands:[...复活选项]}`。

## 11.8 复刻建议

1. ✅ **`sh = sh/(sh+fy)*sh` 递减减伤公式**值得抄，一行解决"防御堆到无敌"的问题。
2. ✅ **部位系统**（15 个部位 × `hert` 倍率 × `crit` 暴击加成）让战斗文案有变化，值得抄。
3. ✅ **五类技能槽**（attack/dodge/parry/force/noweapon）分离，让技能系统有清晰的装配关系，值得抄。
4. ❌ **每角色一条 setTimeout** → 改为全局 tick + 战斗调度队列。理由：可暂停、可限流、便于做战斗回放与日志。
5. ❌ `is_busy`/`is_faint` 等 BUFF 用"持续时间数值 + 时间比较"表示 → 改为统一的 BUFF 对象列表 + 到期时间戳。
6. ⚠️ `recount()` 在 `extends/char/combat.js` 与 `extends/char/user.js` 各有一份且公式不同（`ds` 的 `/5` vs `/10`），属于补丁冲突隐患。
