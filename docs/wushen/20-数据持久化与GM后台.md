## 20.1 数据库（SQLite / better-sqlite3）

### 表结构

| 表 | 关键列 | 说明 |
|---|---|---|
| `users` | `id, name, pwd, phone, state, level, create_time` | `level` 即 `user_level`（GM 等级） |
| `players` | `userid, id, name, title, level, sid, data, create_time, update_time` | **`data` 是整块存档字符串**（非规范化） |
| `players_bak` | 全列 + create/update_time | 删号归档 |
| `servers` | `id, name, ip, port, istest, isdef, create_time, start_time` | 多服配置 |

### 关键 SQL（data/sql.js）

```sql
-- 角色列表
select a.id,a.name,a.title,a.level from players a where a.userid=? and a.sid=?
-- 角色存档读取（⚠️ 只用了 userid，第二个参数被丢弃）
select a.id,a.name,a.title,a.level,a.data,b.pwd,b.level user_level
  from players a left join users b on a.userid=b.id where a.userid=?
-- 角色存档写入
update players set name=?,title=?,level=?,data=? where userid=? and id=?
-- 删号（先归档再删）
insert into players_bak(...) select ... from players where id=? and userid=?
delete from players where id=? and userid=?
```

### GM 命令执行

`SendCommand("call ...")` 系列（readme 示例）：

```javascript
// 执行任意表达式（极危险）
SendCommand("call this.hp=1000000");
SendCommand("call user_id this.add_obj(obj_path,10)");

// 热更新
SendCommand("update cmd/admin/test");
```

> ⚠️ `call` 指令本质是 **在服务器上 eval 任意代码**。GM 后台无二次鉴权（只靠 `user_level`），属于高危接口。

### 后加的 GM 代码位置

- `os/char/character.js:352-1235`（884 行）：`do_gm_command` + `gmCommandHandlers`（emoji 面板、hotload/watch/ban 等）。**占该文件 70%，严重稀释可读性**

## 20.7 复刻建议

1. ❌ **存档整块字符串必须改**：
   - 无法按字段查询（排行榜只能靠内存 `WORLD.DATA.temp_data`）
   - 一个字符串损坏 = 整个角色报废
   - 建议：`players` 表拆出 `attributes` JSON 列 + `items` 子表，或直接用 JSON 列 + 索引
2. ❌ **`call` 指令（远程 eval）必须删除或严格限制**：改为白名单命令集（`set_hp` / `give_item` / `teleport` ...），每条独立鉴权 + 审计日志。
3. ⚠️ **GM HTTP 服务应独立进程 + 独立鉴权**：当前 GM 接口与主 Web 服务同源，且代理是明文 http，错误信息直接回显 `err.message`。
4. ✅ **双写备份（写前备份 + 流式追加）**值得抄，成本极低但能救命。
5. ✅ **按 SERVERID 分数据目录**值得抄，一台机器跑多服互不干扰。
6. ⚠️ `players_bak` 归档表设计不错，但建议加**定期清理策略**。
7. ❌ `getRoleData(userid, id)` 丢弃了角色 id 参数（第 21 册第 5 条），必须修复。
