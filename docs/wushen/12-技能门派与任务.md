### 12.1.2 学习与升级

| 环节 | 函数 | 行 | 逻辑 |
|---|---|---|---|
| 学习条件校验 | `do_learn(me)` | `:207` | 遍历 `learn_condition`；无该字段时退化为"必须已会所有 `can_enables`" |
| NPC 技能装配 | `CHARACTER.skill_map(...)` | `chara_skill.js:7` | `skill_map(["sword",100,"force"])`，第 3 参是 enable 列表 |
| 直接设等级 | `set_skill(skid, level)` | `chara_skill.js:66` | release_prop → 改 level → attach_prop → init_skill → recount |
| 加经验/升级 | `SKILL.add_exp(me, exp)` | `:324` | `need_exp = (lv+1)*(grd+1)*5`（`:46`）；**>100 级才开始计评分** |
| 等级上限 | `skill_limit()` | `chara_skill.js:87` | `round(pow(exp * {20,30,40,50,60,60}[level], 1/3))`（exp<100 时固定 10） |
| **进阶（突破）** | `SKILL.grade_up(me, target)` | `:380` | 需 `level>=1000`；`newLevel = parseInt(sqrt(pot*2/5/(target.grade+1)))` |
| 启用/停用 | `enable_skill(base, skill)` | `chara_skill.js:117` | 先卸旧的 → `enable(me,base)===true` → `baseskill.enable_skill=skill` |
| 遗忘 | `remove_skill(skillid)` | `chara_skill.js:34` | — |
| 生效技能解析 | `init_skill()` | `chara_skill.js:150` | 算出 `attack_skill`/`noweapon_skill`/`dodge_skill`/`parry_skill`/`force_skill` |
| 等级读取 | `query_skill(name, def)` | `chara_skill.js:3` | **`skills[name].level + query_prop(name)`**（装备加成直接加等级） |

**属性挂载三角**（必须遵守，否则 `prop` 重复累加）：

```
release_prop(me, lv)  →  改 level  →  attach_prop(me, lv)
```

```js
                      zj: 20 + parseInt(lv*0.8), desc:"攻击命中后会使敌方忙乱2秒，冷却10秒" } };

this.on_attack_over = function (me, target, par) {   // 触发器

        target.add_status({ id:"busy", is_busy:true, name:"忙乱", duration:2000, downside:true });
        me.set_temp("sk/taijijian/sword", 1, 10000);
    }
}
this.pfm = {
    chan: { name:"缠字诀", distime:20000, enable_skill:"sword",
            weapon_type: WEAPON_TYPE.SWORD, release_time:0, mp:10,

                me.end_attack(target);
            } }
};
```

## 12.3 任务（三套并存的模型）

| 类 | 文件 | 容器 | 定位 |
|---|---|---|---|
| `TASK` | `task/task.js:2` | `WORLD.SYSTEMTASKS[]` | **系统级定时任务**。`create()` 里直接 `this.startup()`；`update()` 先 `stop()` 旧的再 `startup(old)` |
| `USERTASK` | `task/playertask.js:2` | `WORLD.TASKS[]` | **玩家任务面板项**。约定接口 `start(player)`、`query_title()`、`query_desc()`、`query_state()` |
| `EVENTS` | `task/events.js:2` | `WORLD.USER_EVENTS[]` | **全服活动/公告**。静态类，不实例化 |

### query_state 约定（os/task/playertask.js）

```
0 = 不显示   1 = 进行中   2 = 可领取   3 = 已完成
```

### 触发方式

| 触发点 | 代码 |
|---|---|
| 玩家上线 | `USER.init_tasks()`（`user.js:590-595`）遍历 `WORLD.TASKS` 调 `task.on_start(this)` |
| 手动接取 | `USERTASK.RUN(id, player)`（`playertask.js:34`） |
| 按 id 查 | `USERTASK.GET(id)` / `TASK.GET(id)` |
| 事件推送 | `EVENTS.add(item)`（`events.js:7`）→ `notify(item, 0=新增/1=更新)` |
| 事件广播 | `EVENTS.notify(item, act)`（`events.js:21`）遍历 `WORLD.USERS`，`item.check(user)` 过滤，发 `{type:"dialog",dialog:"events",add:1}` |

## 12.4 复刻建议

1. ✅ **技能三档属性**（`query_prop` 学会即生效 / `query_enable_prop` 启用后 / `query_addin_prop` 附加）设计清晰，值得抄。
2. ✅ **`can_enables` + `enable_skill` 装配模型**（特殊技能挂到基本技能槽上）是 MUD 经典设计的正确实现，值得抄。
3. ✅ **绝招（pfm）作为技能的子对象**，带独立 `distime`/`release_time`/`mp`，让战斗有节奏。值得抄。
4. ✅ `#变体 NPC`（`pub/mpguanli#WUDANG`）让一个 NPC 文件服务 11 个门派，内容复用率高。
5. ❌ **任务系统必须重做**。当前三层模型无进度容器，等于"每个任务自己发明一套"。建议引擎提供：
   - `TaskInstance { id, state, progress{}, deadline }` 挂在玩家上
   - 条件/奖励声明式配置（`{kill:{npc:"bj/xiong",count:5}}`）
   - 引擎统一驱动进度与发放
6. ❌ `SKILL[can_enable][grade]` 这种"往类上挂索引"的做法（`skill.js:422`）污染类对象，改为独立的 `SkillRegistry`。
