# 05 · 消息协议字典（上）：连接 · 登录 · 房间 · 物件

> 配套阅读：第 04 册（传输层）。本册列出**服务端 → 客户端**的每一类 JSON 包的真实字段。
> 协议本质：**服务端手工拼接 JS 字面量字符串**（非 `JSON.stringify`），因此存在无引号 key（`{type:"room",path:...}`）与单引号（`"type:'roles'"`）两种风格并存。
> 前端判定是否为 JSON 包：`data[0] == '{' || data[0] == '['`（`src/client.js:166`），否则当纯文本消息处理。

## 5.0 通用约定

| 约定 | 说明 |
|---|---|
| 分发方式 | `Process[data.type](data)`（`src/client.js:96`），**type 名 = 前端 handler 名** |
| 单包上限 | `USER.send` 限制 `text.length < 30240`（`os/char/user.js:26`） |
| 发送者 | `user.send(text)` 强制发（不管状态）；`user.notify(text)` 昏迷时不发（`os/char/user.js:21`） |
| 广播范围 | `send_room` 房内全体；`send_combat` 房内全体（受 `no_combatmsg` 设置过滤） |
| 颜色标签 | 描述文本内嵌 `<hig>`/`<hir>`/`<hic>` 等自定义标签，由 CSS 着色（第 19 册） |
| 可点击命令 | 文本中 `<cmd cmd='go north'>东</cmd>`，前端 `ContainerCommand` 统一拦截（`src/game/main.js:222`） |

### 关键的三视角替换

服务端写文案时用占位符，由 `splitmessage`（`os/char/character.js:88-130`）按接收者身份替换：

| 占位符 | 本人视角(type=1) | 目标视角(type=2) | 第三人称(type=3) |
|---|---|---|---|
| `$N` | 你 | 名字 | 名字 |
| `$n` | 目标名 | 你 | 目标名 |
| `$P` | 你 | `call3()` | `call3()` |
| `$w` / `$W` | 武器名 | 武器名 | 武器名 |
| `$l` | 部位名 | 部位名 | 部位名 |

## 5.1 连接与登录阶段

### 5.1.1 `roles` — 角色列表

- **发送**：`world/extends/login.js:79/82`，登录首包鉴权通过后
- **前端**：`src/process.js:115 Process.roles`

```js
{type:'roles', roles:[{name:'张三', title:'武当派第三代弟子', id:'5f3a2b'}]}
// 无角色：{type:'roles', roles:[]}
```

| 字段 | 来源 |
|---|---|
| `name` / `title` / `id` | `players` 表（`data/sql.js:79` `getRoles`） |

前端行为：渲染 `ul.role-list`；若 `roles.length == 0` 直接跳创建角色面板（`src/process.js:118`）。

### 5.1.2 `login` — 登录成功（进入游戏）

- **发送**：`os/char/user.js:77-89 send_loginmessage()`（**结果被缓存**在 `this.login_message`，重连时复用）
- **前端**：`src/process.js:139 Process.login`

```js
{type:"login", setting:{fontsize:14, ...}, id:"5f3a2b", level:3}
```

| 字段 | 说明 |
|---|---|
| `setting` | 用户设置对象（仅当 `user.settings` 存在时拼入） |
| `id` | 角色 id |
| `level` | 境界等级（0-6，百姓→武神） |

前端行为：`hide2show(".container")` 切到游戏界面；`Setting.load(x.setting)` 应用设置（`src/process.js:141-145`）。

### 5.1.3 `loginerror` — 登录失败

- **发送**：`os/login.js:6-11 login_error()`
- **前端**：`src/process.js:133`

```js
{type:'loginerror', msg:'服务器人数过多，请稍后再试。'}
```

> 发送后**立即 `socket.end()`**（除非 `close=false`）。前端显示 loader 文案。

### 5.1.4 `regist` — 创角结果

- **发送**：`world/cmd/comm/createrole.js`（多处）
- **前端**：`src/process.js:63`

```js
{"type":"regist","result":"角色名称重复，请重新输入"}
```

所有错误文案（`:7,14,17,20,23,28,31,34,37,40,86,91,94`）：请刷新页面重新操作 / 注册信息错误 / 姓名需要是 2-5 个汉字 / 你不能用这个名字 / 名字已有人用 / 四维需在 15-30 之间 / **属性之和必须等于 80** / 创建角色失败。

> 成功时走 `{type:'roles'}` 重新拉列表，不发 `regist`。

### 5.1.5 `deleterole` — 删角结果

- **前端**：`src/process.js:79`，按 `roleid` 移除 DOM 节点

### 5.1.6 `cross` — 跨服跳转

- **发送**：`world/cmd/comm/login.js:55`

```js
{type:'cross', sid:100, pid:'5f3a2b', cross_type:'fb'}
```

- **前端**：`src/process.js:94 Process.cross` → `GameClient.Close()` + `connectServer(serv, pid)` **重连到另一个 WebSocket**。
- ⚠️ 已知字段不一致：`ServerPage` 渲染用 `.id/.name`，`Process.cross` 与 `connectServer` 用 `.ID/.Name`（见第 21 册第 13 条）。

### 5.1.7 `levelup` — 境界提升

- **发送**：`world/extends/char/user.js:94`
- **前端**：`src/process.js:149`

```js
{type:"levelup", level:4}
```

## 5.2 房间与场景

### 5.2.1 `room` — 当前房间（★ 最核心的包之一）

- **发送**：`os/room/room.js:291-315 to_json()`，进入房间 / 重连时
- **前端**：`src/process.js:297 Process.room`

```js
{
  type: "room",
  path: "yz/guangchang",
  name: "扬州城-中央广场",
  desc: "这里是扬州城的中心...",
  commands: [{cmd: "dazuo", name: "打坐"}, {cmd: "cr", name: "完成副本"}]
}
```

| 字段 | 说明 |
|---|---|
| `path` | 房间路径（`area/room`） |
| `name` | `long_name` = `区域名 + "-" + 房间名` |
| `desc` | 描述，可含颜色标签与 `<cmd>` |
| `commands` | 房间 `actions` 表转的数组；副本房额外追加 `{cmd:"cr", name:"完成副本"}` |

> 结果缓存在 `room.json`，改房间描述后需 `exits_changed()` 类操作清缓存。

### 5.2.2 `exits` — 出口列表

- **发送**：`os/room/room.js:275-289 exitsto_roomjson()`
- **前端**：`src/process.js:330 Process.exits`

```js
{type:"exits", items:{north:"北大街", east:"东大街", up:"二楼"}}
```

| 字段 | 说明 |
|---|---|
| `items[dir]` | 方向 → **目标房间名**（不是路径） |

前端两种渲染（`src/process.js:334-354`）：
- `Setting.exits_dir == 1` → 纯文字方向列表
- 默认 → `MAP.CreateExitsMap()` 生成 **SVG 出口图**

> 方向键集合由 `world/cmd/action/go.js:50-58` 定义 20 个：`west/north/south/east/northwest/southwest/northeast/southeast/down/up/westdown/.../enter/out`，另有短写 `s/n/w/e/se/sw/nw/ne/d/u/...`。

### 5.2.3 `items` — 房间物件全量

- **发送**：`os/room/room.js:105-140 items_to_json()`
- **前端**：`src/process.js:224 Process.items`

```js
{type:"items", items:[
   {id:"a1b2", name:"店小二", m:0, l:1, f:0, hp:150, max_hp:150, mp:150, max_mp:150},
   {id:"c3d4", name:"张三", p:1, hp:3200, max_hp:4000, mp:800, max_mp:900},
   0
]}
```

| 字段 | 适用 | 说明 |
|---|---|---|
| `id` | 全部 | 运行时 id |
| `name` | 全部 | `long_name()` |
| `p:1` | 玩家 | 玩家标记 |
| `m` | NPC | `1` = 师父/可查技能（`on_checkskill \|\| on_master`） |
| `l` | NPC | `1` = 有商店（`sell_list`） |
| `f` | NPC | `1` = 有 master |
| `o:1` | NPC | `hp <= 0`（尸体/倒地） |
| `hp/max_hp/mp/max_mp` | 有 `appdend_status` 者 | 血蓝，用于渲染进度条 |

> ⚠️ 数组以字面量 `0` 结尾（`str.push("0]")`），前端必须容忍这个哨兵元素。

### 5.2.4 `itemadd` / `itemremove` — 物件增量

- **发送**：`os/room/room.js:73-103 item_json(item, isin)`
- **前端**：`src/process.js:209 / :194`

```js
{"type":"itemadd",id:"a1b2",name:"店小二",p:1,hp:150,max_hp:150,mp:150,max_mp:150}
{"type":"itemremove",id:"a1b2"}
```

> `isin=true` 才带血蓝；`is_player` 带 `p:1`。

### 5.2.5 `item` — 查看目标详情

- **前端**：`src/process.js:380`，填充 `.item-commands`

点击房间内某物件后服务端下发的详情 + 可用命令列表。

### 5.2.6 `actions` — 底部动作栏

- **前端**：`src/process.js:404`，填充 `.room-commands`

房间的可执行动作集合（如"打坐""采药""拜师"）。

### 5.2.7 `addAction` / `removeAction` — 动作增删

- **前端**：`src/process.js:530 / :532`
- 由 `ITEM.add_action` / `remove_action`（`os/item.js:20/46`）触发，例如装备某道具后出现"使用 XXX"按钮。

### 5.2.8 `cmds` — 通用命令条（★ 交互核心）

- **发送**：`os/char/user.js:59-69 send_commands(...)` / `src` 同名
- **前端**：`src/process.js:406`

```js
{type:"cmds", items:[{cmd:"guid_start", name:"<hig>我需要指引</hig>"},
                     {cmd:"give a1b2 1000 money", name:"人字号客房"}]}
```

**这是本项目最重要的交互模式**：服务端不弹表单，而是下发一组 `{cmd, name}` 按钮，前端渲染成可点击按钮，点击后原样 `SendCommand(cmd)`。

典型用法（`world/npc/pub/xiaoer.js`）：

```js
me.send_commands('zhudian ' + this.id, '上楼', 'xufei ' + this.id, '续房');
//  → {type:"cmds",items:[{cmd:"zhudian xxx",name:"上楼"},{cmd:"xufei xxx",name:"续房"}]}
```

参数规则：**可变参数，两两成对**（cmd, name），`os/char/user.js:60-67` 循环 `i += 2`。

## 5.3 地图

### 5.3.1 `map` — 区域地图数据

- **发送**：`world/cmd/dialog/map.js:59-66 createMapJson`
- **前端**：`src/process.js:418 Process.map`

```js
{type:"map", path:"yz", map:[
   {n:"中央广场", id:"yz/guangchang", p:[0,0], exits:["w2","e2","s","n"]},
   {n:"北大街",  id:"yz/beidajie1", p:[0,-1], exits:["w","e","n"]}
]}
```

| 字段 | 说明 |
|---|---|
| `map[].n` | 房间显示名 |
| `map[].id` | 房间 path |
| `map[].p` | 坐标 `[x, y]` |
| `map[].exits` | 出口编码串，正则 `/^([a-z]{1,2})(\d)?([d\|l])?$/`：方向 + 重复步数 + `d`(虚线)/`l`(粗线) |

请求方式：`SendCommand("map " + map_path)`，`map_path = 当前房间 path 去掉最后一级`（`src/map.js:314`）。

### 5.3.2 `updatemap` — 地图增量

- **发送**：`world/cmd/dialog/map.js:50-53`
- **前端**：`src/process.js:421`

```js
{type:'updatemap', map:'yz', id:'yz/guangchang', n:'中央广场', pos:[0,0]}
```

### 5.4.5 纯文本消息（非 JSON）

任何不以 `{` / `[` 开头的帧都走 `Process.message.push()`：

```js
// src/client.js:86 ReceiveMessage → src/message.js:41 MessageQueue.push
// 每个消息塞进一个 <pre>，jQuery append 会把自定义标签解析成 DOM
```

颜色靠 CSS 元素选择器（`<hig>` → `global.css:249` 的 `#00FF00`），详见第 19 册。
