## 8.1 分层与职责

```
CHARACTER (character.js:3)          消息分发 / 命令分发 / 战斗入口 / 装备技能初始化
  ├─ USER     (user.js:2)           is_player=true；网络输出、★存档序列化、长状态机、随从、元宝、设置、称号
  ├─ NPC      (npc.js:2)            商店(sell_list)、对话、师徒、5 分钟复活、CLONE/GET/CREATE 工厂
  ├─ MONSTER  (monster.js:4)        can_speek=false；bite 系技能；独立部位表 MONSTER_PARTS
  └─ FOLLOWER (follower.js:3)       master/master_name；消息转发给主人；FOLLOWER.STORES 缓存
```

| 类 | 关键差异 |
|---|---|
| `USER` | 有 `socket`、`state` 状态机、`settings`、`cash_money`（元宝）、`titles`（称号）、`user_level`（GM 等级，≥9 为 GM） |

| `MONSTER` | `can_speek=false`，固定 `bite` 系技能，`MONSTER_PARTS` 部位表（`monster.js:102`） |
| `FOLLOWER` | `send()` 会把"你"替换成随从名（`follower.js:34-39`） |

### 8.2.2 派生战斗属性（由 `recount()` 计算）

**玩家版本**（`world/extends/char/user.js:2-32`，★ 真正的实现在这里，不在 os/ 里）：

```js
USER.prototype.recount = function () {
    this.max_hp = parseInt(this.con * 5 + (this.max_mp * this.query_force_rad()
        + this.query_prop("max_hp") + this.query_prop("con") * this.con)
        * (100 + this.query_prop("hp_per")) / 100);
    if (this.hp > this.max_hp) this.hp = this.max_hp;

    this.gjsd = 4000 - this.query_prop("gjsd");
    if (this.gjsd > 500) {
        this.gjsd = parseInt(this.gjsd - (this.gjsd * this.query_prop("gjsd_per") / 100));
        if (this.gjsd < 500) this.gjsd = 500;
    } else { this.gjsd = 500; }

    this.gj = parseInt(this.str + (this.query_prop("gj") + this.query_prop("str") * this.str / 10)
               * (100 + this.query_prop("gj_per")) / 100);
    this.fy = parseInt(((this.str + this.con) / 10 + this.query_prop("fy")
               + this.query_prop("con") * this.con / 10) * (100 + this.query_prop("fy_per")) / 100);
    this.mz = parseInt((this.dex / 2 + this.query_prop("mz")) * (100 + this.query_prop("mz_per")) / 100);
    this.ds = parseInt((this.dex / 2 + this.query_prop("ds") + this.query_prop("dex") * this.dex / 10)
               * (100 + this.query_prop("ds_per")) / 100);
    if (this.dodge_skill && this.dodge_skill.on_recount_dodge)
        this.ds += this.dodge_skill.on_recount_dodge(this);
    this.zj = parseInt((this.str / 2 + this.query_prop("zj") + this.query_prop("str") * this.str / 10)
               * (100 + this.query_prop("zj_per")) / 100);
    if (this.parry_skill && this.parry_skill.on_recount_parry)
        this.zj += this.parry_skill.on_recount_parry(this);
    this.bj = parseInt(this.dex / 10 + this.query_prop("bj_per"));
    this.diff_sh_per = this.query_prop('diff_sh_per');
    this.diff_fy_per = this.query_prop('diff_fy_per');
}
```

> ⚠️ **newmud 侧的一处偏离（2026-10-13 记录，26 册 §25）**：上面 `max_hp` 里
> `query_prop("con") * this.con` 这一项 **没有除 10**，而 `gj` / `fy` / `ds` / `zj`
> 四式的同类项**都除了 10**。newmud 的 `formula.ts` 把这一处也统一除了
> `propScaleDivisor`，即"消掉了 wushen 内部的不一致"。影响面当前为零
> （`prop("con")` 没有生产者），但**性质是未裁定的**：照抄原作还是当有意统一？

**通用版本**（`world/extends/char/combat.js:2-19`）：结构相同，差异只在两处 ——
① **属性加成项的分母是 5 而不是 10**；② **没有 `dodge_skill` / `parry_skill` 钩子**。
即 `ds` 的加成项是 `query_prop("dex") * this.dex / 5`、`zj` 的是 `query_prop("str") * this.str / 5`。

> ★★ **勘误（2026-10-13）**：本行原文写的是「`ds` 用 `dex*dex/5`、`zj` 用 `str*str/5`」——
> **错**。`query_prop("dex")` 是**装备 / 技能给的身法加成**（`props` 里的 `dex` 键），
> 不是身法本身；写成 `dex*dex/5` 会被读成"身法的平方 ÷ 5"，两回事。
> 先天的 `this.dex / 2`、`this.str / 2` 两个版本**完全一致**，所以"分母不同"指的
> 只能是那个加成项（10 vs 5），原文把它和先天项混在了一起。
> **传染面**：这处错描述被原样抄进了 newmud 的 `server/engine/formula.ts` 头部注释，
> 于 2026-10-13 随 26 册 §25 一并订正。教训与 `wushen/06` §6.4.1 同族 ——
> **文档里的"描述"也是断言，错了会一路复制下去**。

| 字段 | 含义 | 备注 |
|---|---|---|
| `gj` | 攻击力 | |
| `fy` | 防御力 | |
| `mz` | 命中 | |

### 8.3.2 序列化 `getData()`（user.js:275-372）

**手工拼 JS 字面量字符串**（不是 `JSON.stringify`，因为要塞 `Function`/`undefined`）：

```
{prop:[<按 SAVE_NUMPROP 顺序的数值...>, 0],
 quit_room:"<path>",
 items:[ [path, id, count, lock?, temp?], ... ],    ← item.save_db(str) 产出
 stores:[...],
 books:["..."],
 skills:{...}, temp:{...}, settings:{...},
 eq:[ ... | null ],                                 ← 按 EQUIP_TYPE 下标定长数组
 titles:[["称号","type",1]],
 follower:[{path,id, prop:[...], items:[...], eq:[...], skills, temp, settings}],
 eq_groups:[...], sk_groups:[...]}
```

返回值：`{id, userid, name, level, title, data}`（`user.js:364-371`）。

### 8.3.3 反序列化 `loadData(role)`（user.js:168-205）

`JSON.toObject(role.data)`（= JSON5.parse）→ 按 `SAVE_NUMPROP` 顺序回填 → `read_items()` 逐条 `OBJ.CREATE(item[0])` + `load_db` + `on_load(this)`。

### 8.3.4 存储

`players.data` 列存整块字符串（**非规范化，整块读写**）。落盘时机见第 02 册 2.6。

> ⚠️ **已确认缺陷**：`util/data.js:107 getRoleData(userid, id)` 调 `DB.getData(userid, id)`，但 `sql.js:110 getData(id)` **只声明一个形参**，SQL 是 `where a.userid=?`。**第二个参数（角色 id）被丢弃**，返回的是该账号下第一条角色。多角色账号选角逻辑存疑（第 21 册第 5 条）。

## 8.7 复刻建议

1. **`recount()` 模式值得抄**："先天属性 + 后天 prop + 各类百分比 → 派生战斗属性"三层结构清晰。但必须：
   - 把公式集中到**一处**（当前散落在两个 extends 文件且不一致）
   - 用配置表驱动而非硬编码公式，便于调参
2. **`temp` 带自动过期值得抄**：BUFF/冷却/任务进度都用它，避免写清理逻辑。
3. **存档整块字符串 ❌ 必须改**：改成分表或至少 JSON 字段。当前 `data` 列一个字符串损坏 = 整个角色报废，且无法按字段查询（排行榜只能靠 `WORLD.DATA.temp_data` 内存排行）。
4. **`temp` 与 `prop` 双轨值得保留**，但要明确边界：`prop` 是持久加成，`temp` 是带 TTL 的临时数据。
