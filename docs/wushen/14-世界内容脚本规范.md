## 14.1 底层执行模型：一切内容文件的共同骨架

### 14.1.1 零 `module.exports`

**全目录 926 个 `.js` 中 `grep -rl "module.exports"` 结果为 0。**

所有内容文件都是"**脚本体**"（script body），由引擎 `vm.compileFunction` 编译后 `func.apply(obj)` 执行，`this` 就是被构造的游戏对象实例。

### 14.1.2 标准四段式

```js
this.inherits(基类);            // ① 第一行声明类型（926 文件全覆盖）
this.set({ ... });              // ② 或直接 this.xxx = ... 赋值
this.xxx = function () { ... }; // ③ 挂方法、钩子
function helper() { ... }       // ④ 文件级私有函数（函数声明提升，可先使用后定义）
```

## 14.3 NPC（world/npc/，159 文件）

### 交互型：店小二（对话 → 分支命令 → 收款）

```js
// world/npc/pub/xiaoer.js（节选）
this.inherits(NPC);
this.set({ name:"店小二", desc:"...", gender:1, age:22,
           per: this.random(20) + 10,        // ★ 每个克隆体随机容貌
           mp:150, max_mp:150, hp:150, max_hp:150 });
this.on_enter = function (me) {
    if (me.query_temp("kezhan")) {
        me.notify("小二一哈腰：这位客官请上楼歇息。");
        return me.send_commands('zhudian ' + this.id, '上楼', 'xufei ' + this.id, '续房');
    }
    me.notify("店小二笑咪咪地说道：这位" + me.call() + "，要住店吗？请进请进。");
}
this.add_action("zhudian", "住店", zhudian);
function zhudian(me, par) {
    me.notify("本店有多种房间提供：\n1. 人字号房每天10两白银...");
    return me.send_commands("give " + this.id + " 1000 money", "人字号客房",
                            "give " + this.id + " 3000 money", "<hic>地字号客房</hic>");
}
this.on_accept = function (me, obj, count) {        // ★ 玩家 give 给他钱时的回调
    if (obj !== "money") return;
    if (count === 1000) {
        me.set_temp("kezhan", 1, 1000 * 3600 * 24);
        me.moveto("kezhan/fang1", me.name + "向客店二楼走去。");
        return true;
    }
    return false;
}
```

### `#` 变体的两个典型

```js
// ① 一个文件派生 4 种丹药  (world/obj/drug/yao.js)
this.on_create = function (path, par) {
    this.drug_type = par ? parseInt(par.substr(1)) : 0;
    this.name = ["再生","暴虐","龟灵","培元"][this.drug_type] + this.name;
}
// → drug/yao#0 ~ #3

// ② 秘籍残页按技能动态生成  (world/obj/book/bc.js)
this.on_create = function (path, par) {
    par = par.substr(1);                        // "book/bc#taijijian" → "taijijian"
    var skill = SKILL.get(par);
    this.skill = skill.id;  this.grade = skill.grade;
    this.name = skill.name + "残页";
    this.combine_count = COMBINED[this.grade];   // [10,10,30,50,100,200,500]
    this.combine_to = "book/book#" + skill.id;
}
```

## 14.7 编码细节

- **多数文件带 UTF-8 BOM**（`\ufeff`），新增文件建议保持一致
- `this` 就是实例，所以 `this.set({...})` 里的值可以引用 `this` 的方法：`per: this.random(20) + 10`
- 文件级 `function helper(){}` 会被提升，因此 `this.add_action("zhudian","住店", zhudian)` 可以写在 `function zhudian` **之前**
- `const EXPS = [...]` 等私有常量常放在文件末尾（靠运行时才调用 `enter` 而避开 TDZ）

## 14.9 复刻建议

1. ✅ **"零 exports 脚本体"范式**对内容作者极其友好（写 10 行就是一个房间），建议保留。但建议加一层薄封装便于工具链：

```js
// 建议的新范式（兼容旧写法）
defineRoom('yz/guangchang', {
    name: '中央广场',
    desc: '...',
    exits: { north: 'yz/beidajie1' },
    npcs: ['pub/xiaoer'],
    on_enter(me) { ... }
});
```
这样就能做静态校验（出口指向的房间是否存在、NPC path 是否有效）。

2. ✅ **`#` 变体参数**极大提升内容复用率（4 种丹药 1 个文件、11 个门派共用 1 个 NPC 文件），值得抄。

3. ❌ **必须补静态校验工具**：当前出口写错房间 path 只有运行时 `ROOM.Get` 返回 `undefined` 才暴露（且 `user.js:246` 的 `rm.is_fb()` 会直接崩）。建议写个 `validate_world.js` 在 CI 跑。

4. ❌ **统一 BOM 处理**：要么全带要么全不带，避免 `vm.compileFunction` 在某些 Node 版本下的解析差异。
