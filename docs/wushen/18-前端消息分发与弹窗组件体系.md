## 18.3 富文本 → 彩色字

1. `ReceiveMessage(x)` → `Process.message.push(x)`（`message.js:41-57`）
2. `MessageQueue.push` 把每个消息塞进一个 `<pre>`，`page.append(x + "\n")`（`message.js:55`）
3. jQuery `append` 会把字符串当 HTML 解析 → 服务端发的自定义标签变成 DOM 元素
4. 颜色靠 CSS **元素选择器**（`global.css:205-398`）

### 自定义标签表

| 类别 | 标签 |
|---|---|
| **基础色** | `NOR` `GRE` `BLK` `BLU` `CYN` `RED` `MAG` `YEL` `WHT` `ORA` |
| **高亮色** | `HIK` `HIB` `HIG` `HIC` `HIR` `HIM` `HIY` `HIW` `HIO` `HIJ` `HIZ` `ORD` |
| **背景色系列** | `B*` 前缀（如 `BHIR`） |
| **特殊展示** | `<mem>`（灰小字）`<line>`（带左右横线的分隔标题）`<cmd>`（下划线可点）`<opt>`（半透明）`<del>`（删除线） |
| **品阶色** | `grade0` ~ `grade6`（`global.css:166-199`） |

> HTML 解析器会把标签名小写化，而元素选择器匹配 ASCII 大小写不敏感，所以混写的 `<hiy>` 和 `<HIY>` 都能生效。

### 富文本里的可点击命令

服务端塞 `<xxx cmd='cmdstring'>文本</xxx>`，前端两段把它变成按钮：

1. `Process.searchItems()`（`process.js:318-328`）：正则从房间描述里**抽取**隐藏命令并入 `room.commands`
2. `game/main.js:222-272 ContainerCommand` 统一委托：

```js
var cmd = elem.attr("cmd");
if (char == "_")       → 内部指令（_confirm / _setting / _trade / _close / _party）
else if (char === '#') → SCRIPT.run(cmd)      // 扩展脚本引擎
else                   → SendCommand(cmd)
```

## 18.4 Dialog 管理器（src/dialog/base.js，137 行）

单例对象 `Dialog`，兼三职：**注册表**、**容器管理器**、**生命周期调度**。

| API | 行 | 语义 |
|---|---:|---|
| `show(name, data)` | 53-75 | 有 data → `dialog.onData(data)`；无 data → 打开/切换/关闭 |
| `select(name)` | 76-85 | 只切 `curItem` 不调 `show`（供 channel 用） |
| `init()` | 86-102 | 首次缓存 5 个 jQuery 元素 + 绑关闭；之后每次显示外壳 |
| `hide()` | 103-106 | **可被 dialog 的 `hide()` 返回 `false` 否决** |
| `footerClick()` | 107-114 | 底部 Tab 点击 → 加 `.select` → `footerChanged(cmd, elem)` |
| `title(html)` | 115-117 | 写标题 |
| `icon(css)` | 118-120 | `"dialog-icon glyphicon glyphicon-" + css` |
| `footer(html)` | 121-123 | `html ? .html(html) : .empty()` |
| `close()` | 124-129 | 隐藏外壳 + 恢复 `.content-room` |
| `injectStyle(css)` | 130-134 | `document.createElement("style")` 注入 head |

### 状态机（单槽位）

```
Dialog.show(name)
  ├─ this[name] 取 dialog
  ├─ !created → init(); created = true                 ← 一次性
  ├─ data 存在 → dialog.onData(data)                   ← 服务端推送路径
  └─ data 为空：
       ├─ already opened && same → hide()              ← 再点即关（toggle）
       └─ else → 旧 dialog.close() + contentElement.empty()  ← 互斥单槽位
                → this.init() 显示外壳
                → curItem = name; dialog.show()
```

## 18.6 三条"非标准"生命周期路径

1. **`Dialog.select(name)`**（`base.js:76-85`）：只设 `curItem`，**不调 `dialog.show()`**。唯一使用者 `dialog/channel.js:13` —— 频道面板要把屏幕上的 `.channel` 元素**物理搬进** dialog（`channel.js:22 insertBefore`），关闭时再搬回（`:29`）。

2. **`inner_show / inner_close` + `createElement()`**：`dialog/message.js:132-140 showChild()` 由父 dialog 手动管理，子 dialog 为 `team / relation / party`（`message.js:116 footerElements = ["message","team","relation","party"]`）。注意 `footerElements[0] === "message"`，即第一个子页是它自己。

3. **`child.show(parentElem)` 父子容器模式**：`dialog/setting.js:113-114` 对 `keys`/`extend` 调用 `this.child.show(this.selectitem)`，子 dialog 反向持有父元素。

### 发送

```js
// src/client.js:68-77
export function SendCommand(cmd) {
    if (IsConnecting) return;
```

## 18.8 扩展脚本引擎（src/script.js，246 行）

用户可以在前端 localStorage 存自定义脚本（`dialog/extend.js`），支持：

| 指令 | 作用 |
|---|---|
| `#wait <ms>` | 等待 |
| `#action <N>` | 执行第 N 个房间动作 |
| `#pfm <N>` | 执行第 N 个绝招 |

配合 `Dialog.extend.trigger(x)`（文本消息触发）和 `Dialog.extend.record(cmd)`（录制指令），构成用户级"半自动挂机"。

## 18.9 复刻建议

1. ✅ **`Process[data.type]` 一行分发**极其简洁，新增消息类型只需加一个同名方法。保留，但建议：
   - 用 `Map` 代替 plain object（避免与工具方法名冲突）
   - 加"未知 type"告警（当前静默忽略）
2. ✅ **自定义标签着色**（`<hig>` → CSS 元素选择器）让服务端写文案极其自由，值得抄。但要注意 XSS：当前服务端文本直接 `append` 到 DOM，**服务端可注入任意 HTML**。建议改为受限标签白名单 + 转义。
3. ✅ **`ContainerCommand` 全局委托**让所有交互统一为 `cmd` 属性，强烈建议保留。
4. ❌ **`new Function` 解析 JSON** 必须改。
5. ❌ **Dialog 生命周期必须统一**：23 个面板 6 种钩子组合，新增面板时无从参考。建议定义 `DialogBase` 接口 + 强制实现。
6. ❌ **必须补心跳与自动重连**。
7. ⚠️ 建议把 `Process` 拆分：当前 542 行混合了分发、DOM 构造、工具函数。建议拆成 `handlers/` + `renderers/` + `state`。
