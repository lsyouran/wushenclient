## 16.1 总体结论

| 维度 | 实际情况 |
|---|---|
| 技术栈 | **Vite 8 + 原生 ES Module + jQuery 4.0**，无 Vue/React |
| 模板引擎 | **无**（未使用 Handlebars/ejs 等） |
| 渲染机制 | **模板字符串 + jQuery DOM 操作**混合，无虚拟 DOM、无数据绑定 |
| 组件化 | 两层自建约定：`Page` 类（只用于登录/游戏两根） + `Dialog` 对象注册表（23 个面板） |
| 样式注入 | 三种并存：静态 CSS、`Page.css` 字段、`Dialog.injectStyle()` 运行时注入 |
| 重绘策略 | **全量重绘**：`$().html(字符串)`，无 diff |

## 16.2 三种 DOM 构建手法

| 手法 | 典型位置 | 示例 |
|---|---|---|
| **① 类 HTML 模板字符串** | 页面骨架、静态面板 | `game/main.js:18-99`、`dialog/score.js:116-330` |
| **② jQuery `$('...')` 构造 + appendTo** | 动态容器/根元素 | `dialog/packet.js:284`、`dialog/team.js:6` |
| **③ 数组 push + `join("")` 拼 innerHTML** | **列表重绘（最主流）** | `dialog/packet.js:349`、`dialog/tasks.js:135`、`dialog/events.js:91` |

第三种是本项目最有代表性的手法：

```js
// 典型列表渲染
create_items: function () {
    var str = [];
    for (var i = 0; i < this.items.length; i++) {
        str.push("<div class='task-item flex-row ");

        str.push("</div>");
    }
    this.element.html(str.join(""));
}
```

## 16.3 组件化：两层模型

```
Level 1  Page 类        src/base/page.js:1-77       —— 只用于「登录 / 游戏」两大根
Level 2  Dialog 注册表   src/dialog/base.js:27-135   —— 23 个子面板的门面与管理
Level 3  普通对象        dialog/*.js 各 export default { ... }  —— 无继承、无类
```

`Dialog` 层**不是继承，是鸭子类型约定**：每个子 dialog 只要按需实现 `init / show / hide / close / onData / footerChanged`，`Dialog.base` 运行时才知道它的存在。所以 23 个 dialog 的钩子**参差不齐**（见第 18 册）。

## 16.4 ★ 页面骨架：从 13 行 HTML 到完整界面

### 16.4.1 index.html（**极简到不可思议**）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>MUD游戏</title>
  <meta name="viewport" content="width=device-width,initial-scale=1.0, minimum-scale=1.0,
        maximum-scale=1.0, user-scalable=no" />
</head>
<body>
  <script type="module" src="./startup.js"></script>
</body>
</html>
```

**没有任何业务 DOM，连 `<div id="app">` 都没有。** 整个 DOM 树由 `MainPage.template` 拼接后一次性 `mount(document.body)`。

> viewport 锁定 `user-scalable=no` —— 手机 App 式 Web 的定位。

### 16.4.2 引导流程（src/startup.js）

```js
import $ from 'jquery';
globalThis['$'] = $;                       // ★ 全局化，所有模块免 import

const page = new MainPage();               // src/main.js:8

```

### 16.4.3 根页面（src/main.js:8-19）

## 16.7 Page 基类（src/base/page.js，139 行）

被 11 个类继承（`LoginPage` 及 9 个子 Page、`GameMainPage`、`MainPage`）。

```js

    const tpl = document.createElement('template');
    tpl.innerHTML = this.render(options);
    parent.append(tpl.content);
    this.$el = parent.lastElementChild;

| 成员 | 行 | 是否实际使用 |
|---|---|---|
| `constructor(filePath)` | 2-10 | ✅ |

| `render(options)` | 29-31 | ✅ |
| `onCompile()` → `_injectStyle()` | 74-76 / 33-39 | ✅（但无子类设置 `css`） |
| `filePath()` | 12-14 | ❌ |

```

   import DialogTasks from './tasks.js';

② 触发（点击底部工具栏）

       const dialog = this[name];
       if (!dialog.created) { dialog.init(); dialog.created = true; }   // 一次性 init
       if (!data) {
           if (this.isShow && name == this.curItem) return this.hide();  // 再点即关
           if (this.curItem && name != this.curItem) {                   // 互斥单槽位

## 16.10 消息流渲染（src/message.js，87 行）

`MessageQueue.create(elem, size=3, max=666)`：

| 参数 | 值 | 含义 |
|---|---|---|
| `size` | 3 | 最多保留 3 个 `<pre>` 页，超出移除最老的 |
| `max` | 666 | 每页计数满 666 行后开新页 |
| `allow_scroll` | true | 用户手动上滚（`wheel`/`touchend`）**自动锁跟尾**，显示 `.scroll-flag` 回底按钮 |

两个实例：主消息流 `Process.message`（`process.js:30`）、频道浮层 `Process.channel`（`process.js:33`，`size=4, max=200`）。

**彩色字的实现**：jQuery `append(字符串)` 会把服务端发的自定义标签（`<hig>`/`<hir>`）解析成 DOM 元素，颜色由 CSS 元素选择器定义（`global.css:205-398`）。因为 HTML 解析器小写化标签名、且元素选择器匹配 ASCII 大小写不敏感，所以混写的 `<hiy>` 和 `<HIY>` 都能生效。

## 16.11 构建配置（vite.config.js）

```js
export default defineConfig({
  root: './src/',                 // 源码根
  publicDir: false,               // ★ 关闭 public 目录 → fonts/img 必须靠 JS/CSS import
  build: {
    outDir: '../www/',            // 产物由 web.js 静态托管
    emptyOutDir: true,
    rollupOptions: { input: { index: 'index.html' } }    // 单入口
  },
  server: { port: 3333, open: true }
});
```

| 命令 | 作用 |
|---|---|
| `npm run dev` | Vite 开发服务器 `:3333` |
| `npm run build` | 构建到 `www/` |
| `npm run preview` | 预览 |

> ⚠️ **开发服务器没有 proxy 配置**。前端 HTTP 用相对路径 `/`（`util.js:3 ProxyHost="/"`），WebSocket 直连 `ws://<ip>:<port>`。所以 `npm run dev` 时 HTTP 接口会 404，只有 `npm start`（Web 服务 8088 同源托管）才完整跑通。

## 16.12 复刻建议

1. ✅ **"HTML 只有 13 行，DOM 全 JS 生成"** 适合 MUD 这类 UI 动态性极强的场景，但要付出代价：无 SEO、首屏白屏时间、无法用 HTML 编辑器预览。建议至少保留一个骨架 HTML。
2. ✅ **`Dialog` 单槽位 + 鸭子类型约定**非常轻，23 个面板总共 6,673 行。保留思路，但**必须统一生命周期接口**（当前 23 个 dialog 钩子参差不齐，见第 18 册）。
3. ✅ **`ContainerCommand` 全局事件委托**（`game/main.js:222`）是个好设计：所有交互统一变成 `cmd` 属性，服务端下发什么就执行什么，前端无需为每个按钮写 handler。强烈建议保留。
4. ❌ **不要抄 `new Function("return "+data)`** 解析服务端 JSON。
5. ❌ **jQuery 全局化（`globalThis.$`）** 虽方便但阻碍模块化，建议显式 import。
6. ⚠️ `injectStyle` 反复注入（多数无去重判断）→ 改为构建期提取到 CSS 文件，或用 CSS Modules。
7. ⚠️ 建议引入 TypeScript：`format_to_pack` 的 13 元素数组、dialog 的鸭子类型，都是类型系统的最佳用武之地。
