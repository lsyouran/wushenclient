# 30 · 测试策略与验证内环

> **本册是"测试该怎么做 / 跑了什么 / 怎么判断结果可信"的唯一入口。**
> 它**不复制**任何具体断言、闸门规则或子系统约定 —— 那些留在各自的原册：
> 闸门规则与假绿家族见 **24 册 §5**；退出码四态见 **26 册 §27**；逐批实现记录见 **26 册**。
> 本册只回答三件事：**测试分几层（各能抓什么 / 抓不到什么）· 改完必跑什么 · 红了怎么判断是真回归还是 flake**。

---

## 1. 为什么要有这一册

项目的**验证内环**（`tsc` → `vitest` → `run-all` → 视情况 `gate:mutation`）此前散在
26 册各批次的"内环"小节里，读者要读完好几批才知道它由哪几步组成、每步的**触发条件**是什么。
把"怎么验证"单独成册，是为了让**改完代码的那一刻**能一站查到"我现在该跑什么"。

★ **本册与 26 册的分工**：26 册记"**这一次**改了 X、红了 Y 条"；本册记"**任何一次**改 X 该跑什么、红了的判读纪律"。
两者是**方法 vs 记录**，不是同一件事的两种写法。

## 2. 测试分层（机制 → 判别力）

按"**跑在什么之上**"分层。层的**缝隙**才是 bug 的藏身处：单测全绿其实只证明了"每块拼图各自正确"，
拼图之间接不上（加载器 / 同端口 / 能关掉）只能靠更外层的**真进程**证。

| # | 层 | 跑在什么之上 | 代表文件 | **能抓什么** | **抓不到什么** |
|---|---|---|---|---|---|
| 1 | 纯逻辑单测 | 无 IO（内存对象） | `engine-base` / `engine-command` / `engine-skill` / `engine-temp` / `engine-formula` / `props` / `validate` / `content` … | 引擎不变量：容器环 / 命令分发 / 记账幂等 / 读档分级 / 公式 | 接缝（进程 / socket / DOM） |
| 2 | 协议 schema 单测 | 无 IO（zod） | `protocol` | 入站包字段的**结构性**约束（版本号比对、方向闭集、去重） | schema 与实际发送点的漂移（那条归闸门 G2.8） |
| 3 | 网络层 | **真 socket**（端口一律 `0`） | `net-e2e` / `net-pipeline` / `net-idle` / `ws-close` / `reconnect` / `session` | 整条链路：**尺寸→限流→分诊→解析(zod)** 顺序、断连判据、背压、限流表回收 | 业务内容（房间 / 指令）是否存在 |
| 4 | 业务端到端 | 真 socket + **真内容** | `login-e2e` | 登录建会话 / 进起始房 / `look` 真看得见 / 掉线注销 —— **用真内容**（合成夹具会掩盖"内容没登记"） | 前端渲染 |
| 5 | 静态 Web 服务 | 真 `node:http` + `fetch` | `static-web` | 服务根 / 302 回跳 / MIME（`<script type=module>` 严格校验）/ 路径穿越 / **安全响应头（L1）** | 浏览器真实行为（jsdom 无布局） |
| 6 | 前端 DOM | **jsdom**（真 `index.html` 结构） | `web-ui` | "屏幕上出现了什么"；XSS 白名单；三块屏互斥 | CSS 布局 / 真实渲染（jsdom 没有布局引擎） |
| 7 | 启动冒烟 | **真 spawn 子进程**（`npm start`） | `launcher` | ① TS 直跑（裸 node 认不认别名）② **同端口** ③ SIGTERM 能退出 | —— 这是"项目能不能跑起来"的**唯一自动化证据** |
| 8 | 静态闸门 | 扫源码 / 测试 / 依赖图 | `tools/gate/run-all.mjs`（G2/G3/G5/G6/G12/G13/G14/G15/G16/G17/G18） | 结构规则：协议对账 / 命名空间隔离 / 禁硬编码 / 依赖方向 / 文档引用 / 标识清单 | 运行时行为（它只看文本结构） |
| 9 | 元闸门（变异测试） | 注入变异后**真跑**闸门 | `tools/gate/mutation-test.mjs` | "每道闸门**真的会红**" —— 死规则（FG-7）与假绿（判据取值域太窄） | 闸门规则**本身**写错（它只证"会红"，不证"红得对"） |
| 10 | 无头浏览器探针 | 真 Chrome（**未入库**） | 临时宿主（见 **26 册 §16.12 / §17.13**） | 真实布局 / 点击链路 —— 补第 6 层"没有布局"的缺口 | —— **临时**，不是可复跑的回归；别把它当"入库的 e2e" |

★ **顺序即依赖方向**：第 1 层不过就别看第 3 层 —— 内层失败会**伪装**成外层失败。
★ **层数不是越多越好**：每多一层就多一处 flake 面。上一层能抓的**绝不**在下一层重复写。

## 3. 验证内环（改完代码按此顺序）

```
cd D:/ts-mud/newmud
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.web.json --noEmit
node node_modules/vitest/vitest.mjs run
node tools/gate/run-all.mjs          # G2/G3/G5/G6/G12/G13/G14/G15/G16/G17/G18
node tools/gate/mutation-test.mjs    # 9–13 min；**动闸门/测试才跑**
```

> ★ **node 用托管版**：`C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-6/node.exe`
> （上面写成裸 `node` 是为了可读；实测双工程 `tsc` 在本版仍 0 错）。

### 3.1 触发条件（**跑哪几步由"动了什么"决定**）

| 动了什么 | tsc | vitest | run-all | **mutation** |
|---|---|---|---|---|
| 只改文档 / 注释 | ✔ | ✔ | ✔ | ✘ |
| 改源码（`server/` `shared/` `world/` `src/`） | ✔ | ✔ | ✔ | ✘ |
| 改测试（`tests/`） | ✔ | ✔ | ✔ | **✔**（铁律 2） |
| 改闸门（`tools/gate/`）或加变异样本 | ✔ | ✔ | ✔ | **✔** |
| 只改 `.workbuddy/` 记忆 / 报告 | ✘ | ✘ | ✘ | ✘ |

★ **铁律 2**：改闸门**或**对应测试 ⇒ 必跑 `gate:mutation`。**SKIP 不算通过**。
★ **未动 `tools/gate/*` ⇒ 不用跑 mutation**（它证的是"闸门会红"，闸门没动就没新命题）。
★ **动过源码 / 测试 / 样本 / 闸门 ⇒ 基线作废重跑**，别拿上一批的绿当本批的证据。
★ 为什么是这个顺序、什么时候可以破例（**只有一种**：闸门先建、让它在实现前红一次），见 **33 册 §33.6**。

### 3.2 迭代提速（**取证不许用**）

- `run-all.mjs` 支持 `--only=<子串>` 只跑匹配的闸门 —— 迭代时把 11 道压到 1 道。
  ★ **取证时不许带 `--only`**：脚本会大声声明"这不是全量结论"，带了的输出**不能当通过证据**。
  ★★ **2026-10-19 才补上**：这段文字**曾经是假的** —— 写的时候 `run-all.mjs` 里
  `grep argv` 零命中，`--only` 只存在于 `mutation-test.mjs`。文档替代码做了一个没人跑过的承诺
  （33 册 §33.3 第 ③ 条"注释/文档也会撒谎"）。本批把它补成真代码，并把上面那句声明做成**必须打印**。
- `mutation-test.mjs` 同理：迭代可窄跑，**收工必须全量**（9–13 min）。

### 3.3 跑长任务的两条工程纪律

- ★ **别 `| head` / `| grep`** 跑长任务 —— 管道提前关闭会触发 **SIGPIPE 中断**子进程。
  做法：**重定向到文件再读**。
- ★ **全量 `vitest` 与 `run-all` 别同时跑** —— `launcher.test.ts` 的子进程与 `run-all` 抢资源，
  `--help` 那条会并发超时（见 §4）。

## 4. 已知 flake 清单（**先复跑，别当回归**）

| flake | 现象 | 真因 | 处置 |
|---|---|---|---|
| `launcher.test.ts` | 全量跑时偶发 1 条超时（**单独复跑必过**） | 与 `run-all`/其它子进程**抢资源**；`--help` 那条最敏感 | 先**单独复跑**；确认是 5s/30s 超时而非断言失败 |
| `static-web.test.ts` | 全量跑时偶发 **2 条**红（首页重定向） | 端口竞争（`fetch` 拿到别的进程的响应） | 单独复跑，**必绿** ⇒ 不是回归 |
| `launcher.test.ts` 超时白等 | 曾经"等满 5s"（已修，**D10 / 26 册 §50**） | `afterEach` 只看 `exitCode`，被信号杀的子进程 `exitCode===null` ⇒ 挂 `once('exit')` 永不 resolve | 已同时看 `signalCode`；见 §5 |

★ **判读纪律**：红的位置**不是**你这批改的文件 ⇒ **先单独复跑那一条**。
复跑绿 = flake（记下来）；复跑仍红 = 真回归（写会红的最小用例再改）。
★ **不许**为了消 flake 去**放宽超时**就收工 —— 那会把"真回归"一起变成绿（FG 家族的同族）。
D10 的处理是先定位到 `signalCode`，不是把 5s 改成 30s 了事。

## 5. flake、假绿、fix-before-assert 的**操作**纪律

这三件是同一个主题（"怎么让证据可信"）的三个切面；本节只讲**怎么做**，
追责与案例在 **24 册 §5.3（FG 系列）** 与 **26 册各批次的"先证会红"小节**。

### 5.1 fix-before-assert（铁律 1 的操作版）

**先写会红的用例并实证会红，再改实现。** 反过来（先改后补用例）= 没有证据。

- ★ **"红"必须是行为红，不是编译红**：需要导出的新符号，先加**导出桩**（原样返回），
  再跑 —— 否则红的只是"import 不到符号"，那证明不了行为。
- ★ **判据锚在"不可能被别的原因满足"的位置**：锚"结果不含坏状态"，不锚"没调用某函数"。
- ★ **回退实证**（本批常用）：实现已写好后，临时把关键判定改成 `if (false && …)`，
  跑到**预期的那几条红**、且**只有那几条红**，再恢复 —— 这才证明判据真的在守那件事。

### 5.2 假绿的两个高频形态（**新写断言前先自问**）

1. **"靠某号 / 某值不存在"** —— 判据要么锚结构，要么锚一个**不会被正常演进碰到**的值
   （变异样本用 `99` 而不是"当年的幽灵号 `28`"，就是因为 `28` 后来被建成了真册）。
2. **不动也绿** —— 写"不该改 X"的断言时先问：**如果我什么都不做，这条是不是也绿？**
   典型：`before=读X(); …; expect(X).toBe(before)`（上一个用例可能已把它写成同样内容）；
   或从未改变的初值出发。修法：**哨兵值 + 起点人为拨到相反状态**，让两个方向都有区分性。
   （这两条是 24 册铁律 8，此处只作操作提示。）

### 5.3 测"能停"时的 Windows 坑

`child.kill('SIGTERM')` 在 Windows **不投递真信号** ⇒ 退出码是 `null`。
⇒ 测"能停"**只断言没超时**，不要断言退出码 / 信号值。
⇒ `afterEach` 里收子进程要**同时看 `exitCode` 与 `signalCode`**（D10 的真因就是这个）。

## 6. 加一条新测试 / 新闸门（checklist 指针）

- **加测试**：先问它属于上面哪一层（§2），别把外层能抓的塞进内层。
  ★ 需要"真 socket / 真内容"就别用合成夹具 —— 夹具会掩盖"内容没登记 / 命令没进表"。
- **加闸门**：规则须自带 `dirs`（扫描=判定范围，见 **24 册 §5.5** 的批次收尾 checklist）；
  证明它**会红**的变异样本要一起加，且要证明**守卫自己**也能红。
- **改动闸门 / 测试后**：`gate:mutation` 全量跑（§3.1）。

## 7. 与本册相关的最常踩的几条（速查）

- ★ 闸门**全绿 ≠ 引用都对**：G15 只判**代码注释**里的册号；G16 判 `docs/` 里的册号与**绑定式** `NN 册 §X` 节号，但**不判裸 `§X`**（指哪一册不可判，见 24 册 §5.1）；G5/G12/G13 曾无**死规则守卫**（扫 0 文件照样绿）—— 见 **24 册 §5.1**。
- ★ 闸门**全绿 ≠ 公共契约都是真的**：**G17** 判 `tools/` 里每个 `export` 有没有外部消费者（死代码 / 假契约），但**只扫 `.mjs`** —— `.ts` 侧的"导出了没人 import"，`noUnusedLocals` 也管不到，属独立批次（见 26 册 §71.5）
- ★ 闸门**全绿 ≠ 标识字典都对**：**G18** 判 32 册的**标记块内**与代码枚举逐字一致；**九组已全部建块**（指令 / 技能 / 服务端帧 / 客户端帧 / 错误码 / 属性键 / kind / 槽 / 保留区，见 26 册 §71.8）。★ 但**块外的人写表仍可能漏**（§32.2 的 76 行、§32.7 的 19 行靠人维护）—— 闸门只保证"§32.13 的名单是全的"，这是主动选择的窄（见 §71.8.5）。★ `npm run ids --check` 核对九组、`--write` 只重写块内
- ★ **机检报 N 条改 N 条是抽样不是收工** —— 只认"写出文件名"的引用，还要问"这形状有没有看不见的写法"。
- ★ **jsdom 没有布局** ⇒ 改 DOM 排布后默认跑**无头 Chrome 探针**（第 10 层，临时宿主）。
- ★ **`BetterSqlite3` 与当前 Node ABI 不匹配** ⇒ 用内置 `node:sqlite`（存档批次相关）。
- ★ 本机**有代理** ⇒ 复核本机服务加 `--noproxy '*'`；无头浏览器加 `--no-proxy-server`。
