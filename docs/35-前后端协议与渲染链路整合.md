**形状规律**：越往下游越"广播"（一个字符串 → 一群人）；越往上游越"单播"。
真正落地到 socket 的**只有一条**：`USER.send` → `socket.send` → `sendData` → `socket.write`。

### 3.2 包的构造方式：**字符串拼接为主**

wushen **没有**统一的"序列化出口"。同一份协议在服务端有两种构造法：

| 构造法 | 用在哪儿 | 证据 |
|---|---|---|
| **手工拼字符串**（多数） | 房间物件、登录包、`item` 详情… | `os/room/room.js:106`（`items_to_json`）`:77`（`item_json`）；`os/char/user.js:77-86`（登录包） |
| `JSON.stringify`（少数） | 聊天 / 频道消息 | `world/cmd/channel/chat.js:40-45`；`tm.js:15` |

拼出来的串**键名常常不加引号**（`{type:'x'}`），因此前端**不能**用 `JSON.parse`
—— 于是它用了 `new Function("return " + data)`（`src/client.js:169`）。
**这两件事是同一个决定的两面**：服务端不保证是合法 JSON ⇒ 前端只能上 eval。

> newmud 把这个决定反过来了：`JSON.stringify` 是**唯一**出口（`server/session.ts:47`），
> 于是前端可以安全地用 `JSON.parse`（`src/net/client.ts:123`）。

### 3.3 示例 · 一个房间物件包是怎么拼出来的（wushen）

`Process.create_roomitem`（**前端**）与 `room.js#items_to_json`（**后端**）是同一件事的两半：

```js
// os/room/room.js:106 附近（后端拼串）
//   items 数组末尾还压了一个 0 哨兵（room.js:139），前端靠它判"数组结束"
// src/process.js:265-296（前端拼 DOM 串）
str.push("<div class='room-item' itemid='" + item.id + "'>");
if (item.max_hp) { /* 血条 .progress.hp / .progress.mp */ }
str.push("<span class='item-name'>"); str.push(item.name); …
```

⇒ 服务端**只给数据**（`id / name / hp / max_hp / …`），
前端**自己拼 DOM 字符串**。这是 wushen 全栈的典型分工：**数据与显示分离得比想象中好**，
真正的问题是**它用字符串拼 DOM**（见 §14 安全面）。

## 4. 前端入站第一跳：分诊

### 4.1 wushen：首字符判定 + `new Function`

```js
// src/client.js:165-174
OnReceived(evt) {
    var data = evt.data;
    if (data[0] == '{' || data[0] == '[') {
        var func = new Function("return " + data + ";");   // ← 等同 eval
        this.OnData(func());
    } else {
        this.OnMessage(data);                              // ← 纯文本
    }
}
```

回调在接线时绑定（`src/client.js:58-59`）：`OnData = ReceiveData`、`OnMessage = ReceiveMessage`。

### 4.2 newmud：同一份判据 + 安全解析

```ts
// src/net/client.ts:116-139
#route(raw: string): void {
  if (!LOOKS_LIKE_JSON_RE.test(raw)) { this.#hooks.onText(raw); return; }
  let parsed: unknown;
  try { parsed = JSON.parse(raw); } catch { this.#hooks.onError(...); return; }
  …
  this.#hooks.onPacket(type, obj);
}
```

判据 `LOOKS_LIKE_JSON_RE` 在 `shared/constants.ts`，**前后端与服务端 `routeFrame` 共用同一份**
（`shared/protocol.ts:1079-1082` 记录了这次单源化：原先两边各写一份，注释自己都警告"分叉会偶尔断连"）。

| 对照点 | wushen | newmud |
|---|---|---|
| 判据 | `data[0] == '{' \|\| data[0] == '['` | `LOOKS_LIKE_JSON_RE`（含前导空白） |
| 解析 | `new Function("return "+data)` | `JSON.parse` |
| 坏包处理 | 抛异常（未捕获 → 静默中断） | `onError()` 明确报错，**不断连** |
| 判据单源 | 前端一份、服务端另一份 | **共享常量**，S10 后单源 |
| 顺序纪律 | 无 | **先量字节 → 再分诊 → 才解析**（`protocol.ts:1046-1050`） |

## 5. 结构化包的分发

### 5.1 wushen：`Process[data.type]` —— 一行查表

```js
// src/client.js:93-98
export function ReceiveData(data) {
    if (Dialog.extend.data_filter(data)) return;   // 扩展过滤器（当前恒 undefined）
    var func = Process[data.type];                 // ★ 方法名 == 包类型名
    func && func(data);                            // ★ 未知 type **静默忽略**
    Dialog.extend.process(data);                   // 扩展脚本 hook
}
```

`Process`（`src/process.js:14-535`）是一个巨型 plain object，
**顶层属性名 == 服务端 `data.type`**。分开派只做一件事：按字符串取方法。
⇒ 写错一个字母就**静默不执行**，没有任何告警。

### 5.2 newmud：显式注册表 + 双向闸门

```ts
// src/process/registry.ts:36-46
export function dispatchPacket(type: string, payload: PacketPayload): boolean {
  const h = handlers.get(type);
  if (h === undefined) return false;              // ← 协议漂移可被上层看见
  try { h(payload); } catch (e) { errorSink(type, e); }  // 一个 handler 崩了不带走整条流
  return true;
}
```

注册与闸门：

| 机制 | 文件 | 作用 |
|---|---|---|
| `registerHandler(type, fn)` | `src/process/registry.ts:22-25` | 重复注册**抛错**（不许两个 handler 抢一个 type） |
| handler 聚集处 | `src/process/index.ts:27-31` | 5 个副作用 import：`world / role / combat / social / system` |
| **G2 闸门** | `tools/gate/g2-protocol.mjs` | 扫 `src/process/**` 的 `registerHandler('x')`（**剥离注释后**），与 `SERVER_PACKET_TYPES` 做**双向**差集 |
| **G2.8 台账** | `shared/protocol.ts:671-706` | `SERVER_PACKET_UNWIRED`：声明了但**还没有生产者**的包（截至 2026-10-20 共 **21 条**），接线一个销一行，**只许缩短** |

> `registry.ts` 之所以是**单独一个文件**：ESM 的 `import` 会提升到模块体之前，
> 若注册表本体与 handler import 同处一个模块，handler 反过来 import `registerHandler`
> 就会在 `new Map()` 之前跑到 → `ReferenceError: Cannot access 'handlers' before initialization`。
> 拆开后依赖单向：`handlers/* → registry`，`index.ts → registry + handlers`（`registry.ts:1-15`）。

## 9. 文本标签协议（颜色 / `<mem>` / `<line>` / `<CMD>`）

### 9.1 标签在**服务端生成**，浏览器原生渲染

wushen 的富文本**不是**前端解析出来的：服务端直接拼 `<hir>`、`<CMD onclick=…>` 这类标签
送进下行文本（如 `os/char/combat.js:36`、`chara_skill.js`、`room.js`）。
前端**没有标签解析器** —— 靠浏览器"把未知元素当普通元素收下"+ CSS 元素选择器着色
（`src/styles/global.css:201,205-293`）。

| 类别 | 标签 | CSS 位置 |
|---|---|---|
| 基础色 | `NOR GRE BLK BLU CYN RED MAG YEL WHT ORA` | `global.css:205-243` |
| 高亮色 | `HIK HIB HIG HIC HIR HIM HIY HIW HIO HIJ HIZ ORD` | `global.css:249-293` |
| 版式 | `<mem>`（灰小字）、`<line>`（带横线分隔标题）、`<opt>`（半透明）、`<del>`（删除线） | `global.css:158-161, 245-247` |
| 品阶边色 | `grade0` ~ `grade6` | `global.css:166-199` |

> HTML 解析器会把标签名**小写化**，而 CSS 元素选择器对 ASCII 大小写**不敏感** ——
> 所以 `<hiy>` 与 `<HIY>` 都能生效（18 册 §18.3 注）。

### 9.2 富文本里的可点击命令（wushen）

服务端塞 `<xxx cmd='cmdstring'>文本</xxx>`，前端**两段**把它变成按钮：

1. `Process.searchItems()`（`process.js:318-328`）—— 用正则
   `/<\w{3}\scmd=['"](.+?)['"]>(.+?)<\/\w{3}>/g` 从**房间描述**里抽出隐藏命令，并入 `room.commands`；
2. `game/main.js:222-272`（`ContainerCommand`）—— 全局事件委托，按 `cmd` 首字符分派：

```js
var cmd = elem.attr("cmd");
if (char == "_")       → 内部指令（_confirm / _setting / _trade / _close / _party）
else if (char === '#') → SCRIPT.run(cmd)      // 扩展脚本引擎
else                   → SendCommand(cmd)     // 发给服务端
```

### 9.3 newmud 的处置：白名单解析器，**不带属性**

| 点 | wushen | newmud |
|---|---|---|
| 标签怎么变成节点 | 浏览器 HTML 解析（jQuery `.html()/append`） | 自写白名单解析器 `ui/markup.ts:127-198` |
| 名单外标签 | **照常建节点**（`<script>` 就是脚本节点） | **原样当文本显示**（`markup.ts:168-171`） |
| 文本节点 | HTML 解析 | `createTextNode`（`markup.ts:139`），**从不经过 HTML 解析器** |
| 标签属性 | 落 DOM（`cmd` 成为真属性 → 真按钮） | **不落 DOM**（`markup.ts:189-191`） |
| 自由文本里的按钮 | ✅ `<CMD cmd=…>` | **已删除**（`KNOWN` 里没有 `CMD`，`markup.ts:41`；论证见文件内 `§CMD` 一节，审查 S1） |
| 嵌套深度 | 无限制 | 上限 32 层，超出按文本（`markup.ts:86, 184-187`） |
| 可点按钮从哪来 | 服务端文本 | **仅** `CmdItem` 结构通道（`cmd` → `dataset.cmd`，文案 → `textContent`） |

> **为什么删掉文本里的按钮（S1）**：它**自己就在白名单里**，于是躲过了白名单的全部防线；
> 而角色名经 `$N` 进**每一句**播报 ⇒ **不用开口**，站在房间里就在给全房间植按钮。
> 删除代价为零：全仓本来就没有 `<CMD>` 生产者。详见 `ui/markup.ts:45-68`。

## 11. 出站方向：客户端 → 服务端

### 11.1 wushen：**纯文本指令**，握手用空格分隔的裸串

```js
// src/client.js:68-77
export function SendCommand(cmd) {
    if (IsConnecting) return;
    if (!GameClient || !GameClient.Connected()) {
        LastCommand = cmd;                                  // 缓存，重连后补发
        ReceiveMessage("<red>连接中断，正在重新连线...</red>");
        return connectServer(SelectedServer);               // ★ 懒重连
    }
    Dialog.extend.record(cmd);                              // 扩展引擎录制备注
    GameClient.Send(cmd);                                   // 裸文本，无信封

```

**连接建立后的首包三种形态**（`src/client.js:31/34/36`）：

| 场景 | 首包内容 |
|---|---|
| 未选过角色 | `<userid> <token>` |
| 指定角色 / 跨服 | `<userid> <token> <pid> <server.ID>` |
| 已有角色（重连） | `<userid> <token> <Process.player>` |

服务端解析：`SessionKey = "u"`、`SessionToken = "p"`（`src/client.js:9-11`），
`<token>` 是 **AES-128-CBC 加密的 base64**，明文为 `id%name%pwd%loginTime%level`
（`os/login.js:12-35`，key = userid 前 16 字符，iv = `__CONFIG.DESIV`）。
跨服判定靠**字段个数**（`str.length === 4`，`world/extends/login.js:39-47`）。

服务端入口链：`WORLD.request` → `user.command`（`os/world.js:75`；`os/char/character.js:136`）；
登录期走 `wait_input = USERLOGIN.check_session`（`os/world.js:53`；`world/extends/login.js:6`）；
指令最终进 `CHARACTER.do_command` → `WORLD.COMMANDS[cmd]`（`character.js:156-188`，
命令注册表 `os/command.js:20-31`）。

### 11.2 newmud：两种形态，按**同一份判据**分流

```ts
// src/net/client.ts:153-166
public sendCommand(text: string): void {
  const command = text.trim();
  if (command === '') return;
  if (LOOKS_LIKE_JSON_RE.test(command)) {          // ★ 首字符像 JSON
    this.sendPacket({ type: 'command', cmd: command });   // 走 command 包
    return;
  }
  this.#raw(command);                              // 否则明文
}
public sendPacket(body) { this.#raw(JSON.stringify({ v: PROTOCOL_VERSION, ...body })); }
```

> 为什么要分流：服务端 `routeFrame()` 也按首字符判（`/^\s*[[{]/`）——
> 一条长成 JSON 的**明文指令**会被服务端判成 JSON → `JSON.parse` 抛 → 主动断连。
> 玩家敲 `{公告}` 或粘贴带前导空格的 JSON 都会踩到。这是 **S10（2026-10-16 审查）** 的处置。

| 对照点 | wushen | newmud |
|---|---|---|
| 形态 | 只有明文裸串 | 明文 + 三种 JSON 包 |
| 信封 | 无 | `{v, type, …}`，版本**精确等于** `PROTOCOL_VERSION` |
| 登录 | 空格分隔的裸串（内含加密 token） | `ClientLoginPacket {token, role_id}`，**不含密码** |
| 心跳 | 无 | `ClientPingPacket {t}` |
| 指令包 | 无 | `ClientCommandPacket {cmd}`（≤512 字符，禁控制字符） |
| 服务端校验 | 无 | `ClientPacketSchema`（`protocol.ts:875-879`，discriminated union） |
| 解包 | 前端 `Runtime` 直接 `Send(cmd)` | `sendPacket` 统一 `JSON.stringify` |

## 16. 复刻 / 迁移要点（从这份整合里得出的可执行结论）

1. **保留 `dialog` 通用容器 + `Dialog.show(name,data)` 的模式** —— 它是全协议里
   唯一"加面板不用改协议"的机制。但必须补**面板名闭集**（`DialogNameSchema`）与逐面板载荷类型。
2. **保留"服务端给数据、前端拼界面"的分工** —— wushen 这一点做对了，
   坏的是**拼 DOM 的手段**（字符串 + HTML 解析），不是分工本身。
3. **`Process[type]` 一行分发值得保留形式，但要换实现**：用 `Map` 而不是 plain object
   （避免与工具方法名冲突），并对**未知 type 告警**（wushen 是静默忽略）。
   newmud 的等价物是 `dispatchPacket()` 返回 `false` + G2 闸门。
4. **必须改的两条**：`new Function` → `JSON.parse`；服务端文本 → 白名单解析器。
5. **必须补的两条**：心跳（`ping`）；出站/入站体积上限。
6. **"声明未实现"要记账**：`pay` 这类"前端写好、后端从没接线"的包，
   在 wushen 里没有任何机制能发现。newmud 的 `SERVER_PACKET_UNWIRED` + G2.8 就是答案。
7. **回收粒度各取所需**：wushen 的分页（666×3）与 newmud 的逐行（400）都成立，
   真正不能省的是**"贴底才跟随" + 回底浮标**这两条行为。
