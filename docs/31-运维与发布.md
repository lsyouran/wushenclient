## 1. 一句话拓扑

**单进程**：一个 Node 进程同时提供**静态资源**与 **WebSocket**，**同一个端口**。

```
浏览器 ──(http, 同端口)──> 静态资源(dist/web/)
       ──(ws,  同端口 /ws)> WebSocket 升级 ──> hub ──> session ──> 引擎
```

★ **为什么必须同端口**：前端默认连接地址是**同源**的（`ws://${location.host}/ws`）。
拆成两个端口的表现是"**页面能开、点了进不去**"（`tools/start.mjs` 与 `launcher.test.ts` 都把这条钉住）。
★ **WebSocket 端点是 `/ws`**（不是根路径）：服务端单点定义在 `server/net/ws-server.ts` 的 `WS_PATH`；
  前端与 `cli.ts` 各持一份字面量（不共享模块），**改动时三处一起看**。
★ **对外发布的标准拓扑**：本进程**只监听 loopback**，前面加**反向代理做 TLS 终止**
  （见 §3）—— 因为本进程**不实现 TLS**。

## 2. 运行参数全表

启动：`npm start`（`prestart` 自动先 `npm run build:web`）。给 npm script 传参必须用 `--` 隔开：

```bash
npm start -- --port 9000 --host 0.0.0.0
npm start -- --help          # 打印下表
```

| 参数 | 作用 | 缺省 | 校验范围 |
|---|---|---|---|
| `--port <n>` | 监听端口（静态 + WS 同端口） | `8123` | `0`–`65535`（`0` = 系统分配） |
| `--host <addr>` | **监听地址** | `127.0.0.1` | 要对外**必须显式**给（如 `0.0.0.0`） |
| `--no-web` | 只提供 WebSocket，不发前端 | 关 | —— |
| `--web-root <dir>` | 前端产物目录 | `<项目根>/dist/web` | —— |
| `--max-connections <n>` | **全局**同时在线连接上限 | `MAX_CONNECTIONS`(200) | `1`–`100000` |
| `--max-connections-per-ip <n>` | **同一地址**连接上限 | `MAX_CONNECTIONS_PER_IP`(8) | `1`–`100000` |
| `-h`, `--help` | 打印 usage 退出 | —— | —— |

★ 缺省值来自 `server/cli.ts`（`DEFAULT_PORT` 等）与 `shared/constants.ts`（`MAX_CONNECTIONS*`）——
  **单源真相**，本表只是搬运，改常量这里跟着改（没有闸门守这张表，属人工纪律）。
★ `--host` 缺省 **`127.0.0.1`** 是**有意的安全缺省**：默认只本机可访问。
  要对外才显式改 —— 而"显式改"的那一刻，就是**必须走一遍 §4 安全清单**的时刻。

## 3. 对外发布（反向代理 + TLS）

本进程**不做 TLS** ⇒ WebSocket 明文（`ws://`）= **token 与全部对话明文**。
对外部署**必须**在反向代理处终止 TLS，把 `wss://` 转成 loopback 上的 `ws://`。

**最小 Nginx 骨架**（要点：升级头 + 读超时 ≥ 空闲心跳间隔 + 只代理到 loopback）：

```nginx
server {
    listen 443 ssl;
    server_name mud.example.com;

    ssl_certificate     /etc/letsencrypt/live/mud.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mud.example.com/privkey.pem;

    # 静态资源与页面
    location / {
        proxy_pass http://127.0.0.1:8123;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket（端点是 /ws，不是根）
    location /ws {
        proxy_pass http://127.0.0.1:8123;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;   # ★ 必须 ≥ 服务的空闲心跳间隔，否则长挂机会被代理掐断
    }
}
```

★ **WebSocket 的两个必备头**（`Upgrade` / `Connection: upgrade`）漏一个 = 升级失败 =
  浏览器那句"页面能开、点了进不去"；`proxy_read_timeout` 漏了 = 玩家挂机一会儿就被断开。
★ **前端走相对地址**（`ws://${location.host}/ws`），所以 TLS 之后**前端零改动**就变成 `wss://`。

### 3.1 ★★ 反向代理会压平 `remoteAddress`（**per-IP 限流的已知退化**）

服务端按 `req.socket.remoteAddress` 取客户端地址做 **per-IP 连接上限**。
**一旦加了反向代理，所有连接对服务端都来自代理的地址** ⇒ `--max-connections-per-ip`
**退化成"对所有客户端合计生效"**（8 个连接就把所有人挡在门外）。

- 当前**未读取** `X-Forwarded-For`（代理头可被伪造，信任它要配套"可信代理层数"逻辑）。
- ⇒ **现状**：上代理后要么把 `--max-connections-per-ip` 调大，要么等**账号/暴露批次（T12）**
  落地"可信代理 + 真实 IP 解析"。**这是有意的未做项，不是 bug**，记在此处免得部署时踩。
- ★ 同理，`--host` 后**本进程自己的 Origin 校验**（`isSameOriginRequest`）仍按 Host 判定 ——
  代理要**透传 `Host`**（上面的骨架里已带），否则合法请求会被判成跨源。

## 4. 对外发布前的**安全清单**（逐条勾）

| # | 项 | 现状 | 依据 |
|---|---|---|---|
| 1 | **TLS 终止**（`wss://`） | ⛔ **未做**（本进程无 TLS；靠代理，见 §3） | 26 册 §4（安全前置） |
| 2 | **安全响应头** | ✅ **已发**（L1，静态服务四段响应统一带） | `server/static.ts#SECURITY_HEADERS`、测试 `static-web.test.ts` |
| 3 | 监听地址**不裸奔** | ✅ 缺省 loopback；对外才显式 `--host` | `cli.ts` / `ws-server.ts` |
| 4 | WS 只认 **`/ws`** | ✅ 非该路径不升级 | `ws-server.ts#WS_PATH` |
| 5 | **同源校验**（防跨站 WS 连接） | ✅ `isSameOriginRequest` | 26 册 §30.2（N2） |
| 6 | **限流**（连接数 / 每 IP / 每 5s 帧） | ✅ 全局 + per-IP + 速率三档 | `shared/constants.ts`、§3.1 的代理退化说明 |
| 7 | **账号 + token 验签 + 角色存档** | ⛔ **未做**（T12） | 28 册（存档设计）、26 册 §14 |
| 8 | 出站**背压**不静默丢弃 | ✅ 超限关连接 + 记账 | `MAX_BUFFERED_BYTES`、26 册 §16.4 |

### 4.1 安全响应头（已发，值如下）

由 `commonHeaders()` 统一附加到 **200 / 404 / 204 / 302** 四段响应：

| 头 | 值 |
|---|---|
| `x-content-type-options` | `nosniff` |
| `referrer-policy` | `no-referrer` |
| `x-frame-options` | `DENY`（点击劫持 · 旧语法） |
| `content-security-policy` | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` |
| `cache-control` | `no-store`（开发期"改完刷新就看到"；上生产可按资源类型再议） |

★ **这套 CSP 不需要 `unsafe-inline` / `unsafe-eval`**，因为前端**逐条对齐**过：
  无 `<style>` 块 / 无 `style="…"` / 无内联事件 / 无 `eval`；血量条走 **CSSOM**（`element.style.width`，
  CSP 不拦）。这条由 `static-web.test.ts` 的**通扫**钉住 —— 谁哪天加了内联写法，那里红。
★ `x-frame-options` 与 `frame-ancestors` 是**同一策略的新旧两版**，刻意都发（老/新浏览器各认一个）。
  **不是两份真相**，值必须一致（都表示"不许任何页面嵌我"）。

## 5. 容量与阈值（**改这些先看单源**）

| 阈值 | 值 | 单源 | 备注 |
|---|---|---|---|
| 全局连接上限 | 200 | `shared/constants.ts#MAX_CONNECTIONS` | `--max-connections` 可覆盖 |
| 每 IP 连接上限 | 8 | `shared/constants.ts#MAX_CONNECTIONS_PER_IP` | 代理下退化，见 §3.1 |
| 房间容量 | 50 | `engine/room.ts#DEFAULT_ROOM_CAPACITY` | 玩家背包 50 / NPC 10，见 **29 册 §29.4** |
| 出站积压上限 | 1 MiB | `MAX_BUFFERED_BYTES`（`socket.bufferedAmount`） | **运行时够得着**的那一档；超限关连接 |
| 出站队列条数 | 256 | `MAX_OUTBOUND_QUEUE` | 另一档，**非运行时判据**（见常量注释） |
| `busy`（动作锁）上限 | 15 s | `engine/character.ts#BUSY_MAX_MS` | 非法值抛 / 超限钳 |
| 属性量级上限 | 1e8 | `engine/props.ts#MAX_PROP_MAGNITUDE` | 读档入口闸门（E11） |
| 每 5s 入站帧上限 | 见常量 | `RATE_LIMIT_PER_5S` | 限流在**解析之前** |

★ **两档背压各管一段**（别把条数那档当容量规划用）：条数档是"某调用方只 enqueue 不 drain"的兜底；
  运行时真正够得着的是**字节档**。详见 26 册 §16.4 与常量注释。

## 6. 启动链与运行环境

```
npm start
  └─ prestart: npm run build:web   （tsc -p tsconfig.web.json → dist/web/）
  └─ node tools/start.mjs          （注册 TS 解析钩子 → server/cli.ts）
       └─ server/cli.ts → main()   （解析参数、装配、listen）
```

| 项 | 值 |
|---|---|
| **Node 门槛** | **≥ 22.15.0**（用到 `module.registerHooks`）—— 由 `package.json#engines` 与测试共同钉住 |
| 构建步骤 | **无**。服务端直跑 `.ts`（自研零依赖类型剥离加载器，`tools/dev/ts-loader.ts`） |
| 服务根 | `dist/web/`（**不是** `dist/web/src/` —— 弄错就是白屏 + 404）；`GET /` → **302** → `/src/index.html` |
| 页面地址 | `http://127.0.0.1:8123/`（默认端口） |
| WS 地址 | `ws://127.0.0.1:8123/ws`（**同一端口**） |

★ 原理与踩过的坑见 **26 册 §17**；`server/main.ts` 是**纯工厂，不能直跑**，入口链是 `cli.ts → main()`。
★ **同端口**这件事对反代是友好的：一个上游地址同时覆盖页面与 WS。
