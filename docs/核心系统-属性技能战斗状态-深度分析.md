## 一、属性系统

### 1.1 三层属性模型（核心数据结构）

角色属性并非单一对象，而是**三层叠加**：先天五维 → 后天 `prop` 映射 → 临时 `temp` 值，外加一个战斗专用栈 `combat_props`。

**第一层：先天五维**（构造函数默认值，[character.js#L3-L10](file:///d:/wushen/wushen/WuShenMud/os/char/character.js#L3-L10)）

```js
this.hp = this.max_hp = 100;
this.mp = this.max_mp = 100;
this.str = this.con = this.dex = this.int = 20;
this.money = 0;
```

五维含义（[const.js#L35-L43](file:///d:/wushen/wushen/WuShenMud/os/const.js#L35-L43)）：`str`=臂力、`con`=根骨、`dex`=身法、`int`=悟性。另有 `str1/con1/dex1/int1` 表示「先天值」，专用于学习/装备条件判定（不参与战斗计算）。

**第二层：后天属性 `prop`**（[chara_prop.js#L3-L19](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L3-L19)）

```js
CHARACTER.prototype.add_prop = function (p, v) { ... this.prop[p] = v1 + v; }   // L3
CHARACTER.prototype.query_prop = function (name) { return this.prop[name] || 0; } // L15
```

`prop` 是一个**扁平 key→数值 映射**，键名即 [const.js#L35-L114](file:///d:/wushen/wushen/WuShenMud/os/const.js#L35-L114) 中的 80 余个条目（`gj`/`fy`/`mz`/`diff_sh_per`/`add_sh_per`…）。装备、技能、buff、药丸全部通过 `change_prop` 往这里加数字。

**第三层：临时值 `temp`**（[chara_prop.js#L30-L62](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L30-L62)）

带过期时间 `e` 的临时值，`query_temp` 命中即返回、过期即清空：

```js
query_temp(name, def) { var item = this.temp[name];
    if (item && item.e) { if (Date.now() <= item.e) return item.v; this.temp[name]=null; return def; }
    return item ?? def; }
```

用途：`pfm/<id>` 绝招冷却、`exp_up` 经验加成、`dazuo_per` 打坐加成、`fb2` 位图解锁标记等。

**第四层：战斗临时属性栈 `combat_props`**（[chara_prop.js#L115-L137](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L115-L137)）

```js
add_combat_prop(name, val) { this.add_prop(name, val);
    this.combat_props.push([name, val]);  // 记录流水，便于整体回滚
    if (name === 'max_hp') this.max_hp += val; }
clear_combat_prop() { /* 逐条取负回滚，max_hp 反向扣回，最后 recount() */ }
```

设计意图是「战斗开局发放、结束整体撤销」的临时增益。玩家侧覆写见 [user.js#L828-L845](file:///d:/wushen/wushen/WuShenMud/os/char/user.js#L828-L845)（差异：玩家版本 **不** 处理 `max_hp`）。

### 1.2 派生属性重算 `recount`（最关键的数值函数）

派生战斗值（`gj/fy/mz/ds/zj/bj/gjsd`）**不实时计算**，而是由 `recount()` 在属性变更时一次性汇总，缓存在实例字段上，供战斗循环直接读取。这是性能优化，也是所有数值怪象的根源。

**NPC 版**（[world/extends/char/combat.js#L2-L19](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L2-L19)）：

```
gjsd = 4000 - prop("gjsd")；再按 gjsd_per 缩减；下限 500
gj  = str + (prop("gj")  + prop("str")*str/10) * (100+prop("gj_per"))/100
fy  = (str+con)/10 + prop("fy") + prop("con")*con/10            → 再乘 (100+fy_per)/100
mz  = dex/2 + prop("mz")                                        → 再乘 (100+mz_per)/100
ds  = dex/2 + prop("ds") + prop("dex")*dex/5                    → 再乘 (100+ds_per)/100
zj  = str/2 + prop("zj") + prop("str")*str/5                    → 再乘 (100+zj_per)/100
bj  = dex/10 + prop("bj_per")
diff_sh_per = prop('diff_sh_per'); diff_fy_per = prop('diff_fy_per')
```

**玩家版**（[world/extends/char/user.js#L2-L32](file:///d:/wushen/wushen/WuShenMud/world/extends/char/user.js#L2-L32)）在上述基础上：

- 增加 `max_hp` 计算（见下）；
- `ds` 的 `prop("dex")` 系数改为 **`/10`**（NPC 是 `/5`，见 L19）；
- `zj` 的 `prop("str")` 系数改为 **`/10`**（NPC 是 `/5`，见 L23）；
- 增加 `dodge_skill.on_recount_dodge()` 与 `parry_skill.on_recount_parry()` 钩子（L20-L26）。

```js
max_hp = parseInt( con*5 + ( max_mp*query_force_rad()
        + prop("max_hp") + prop("con")*con ) * (100+prop("hp_per"))/100 );
```

其中 `query_force_rad()`（[chara_prop.js#L20-L24](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L20-L24)）返回内功的 `force_rad`（默认 0.1），**这就是「内力转化为气血」机制**：太极神功 `force_rad=0.8` 即 80% 内力上限折成气血（[taijishengong.js#L8](file:///d:/wushen/wushen/WuShenMud/world/skill/wudang/taijishengong.js#L8)）。

> ⚠️ **实锤隐患**：`recount` 存在三个版本（NPC / 玩家 / 比武复制体 [biwu.js#L264-L296](file:///d:/wushen/wushen/WuShenMud/world/cmd/extend/biwu.js#L264-L296)），三者公式**互不一致**（ds/zj 系数、diff_sh_per 软上限、diff_sh_per2 是否叠加）。同一角色在「日常战斗 / 比武场 / 镜像复制体」中的防御数值可能不同。

### 1.3 属性写入链路：`change_prop` 的技能特例

`change_prop`（[chara_prop.js#L64-L98](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L64-L98)）是唯一的批量属性入口，对 `skill` 键有特殊分支：

```js
case "skill":  // 装备/技能带 [skill] 属性时 → 直接提升对应武功等级
    var lv = this.query_skill(sk, 0);
    if (!lv) { this.add_prop(sk, ±sks[sk]); continue; }
    sk_base.release_prop(this, lv);        // 先卸旧属性
    this.add_prop(sk, ±sks[sk]);           // 改等级
    sk_base.attach_prop(this, this.query_skill(sk, 0));  // 再挂新属性
```

即「提升技能等级 → 触发该技能属性重新结算」。这里是**属性与技能系统的强耦合点**（详见 5.1）。

其余键走 `default` 分支，直接 `add_prop(item, ±prop[item])`，无任何上限/类型校验。

每次变更后绝大多数路径会调用 `recount()` 刷新派生值。

### 1.5 优点

1. **扁平映射 + 字符串键**：`prop` 无需为每个属性建字段，扩展一个属性只要在 `const.js` 加一行，装备/技能/buff 全部复用同一套 `change_prop`，扩展成本极低——这是 MUD 快速迭代的正确取舍。
2. **`recount` 缓存**：战斗循环（每秒多次）只读字段，不重复做浮点运算，性能好。
3. **正负对称**：所有 `add` 都有对应 `-add`（`attach_prop`/`release_prop`、`add_combat_prop`/`clear_combat_prop`），理论上可无损回滚。
4. **临时值带过期**：`temp` 的 `e` 字段让 buff/冷却类状态无需额外定时器即可自然失效。

### 1.6 缺点 / 隐患

1. **`recount` 三份实现不一致**（1.2 节）：NPC 玩家 ds/zj 系数差一倍；`diff_sh_per` 只有比武版有 80 软上限；`diff_sh_per2` 只有比武版生效。**同一设计意图散落三处、彼此矛盾**，极易产生「数值对不上」的玄学 bug。
2. **`change_prop` 的 `skill` 分支无重入保护**：`release_prop` → `add_prop` → `attach_prop` 链条中，若技能自身属性又含 `skill` 键，可能递归/叠加异常。
3. **`clear_prop` 全清 + 无版本号**：`clear_prop()`（[L12](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L12)）直接 `this.prop = {}`。若某处忘记 `recount`，派生值会停留在旧状态，静默不一致。
4. **玩家 `add_combat_prop` 与 NPC 行为不一致**：NPC 版本处理 `max_hp`，玩家版本不处理（[user.js#L828](file:///d:/wushen/wushen/WuShenMud/os/char/user.js#L828) vs [chara_prop.js#L115](file:///d:/wushen/wushen/WuShenMud/os/char/chara_prop.js#L115)），玩家战斗临时加血上限会得到错误结果。
5. **无属性上限/下限**：`add_prop` 直接相加，`diff_sh_per` 可被叠到 100%+（除非走比武版软上限），存在「免伤 100% 无敌」的理论漏洞。
6. **`prop` 键无命名空间**：装备、技能、buff 共用一个扁平字典，同名键互相污染，调试时难以溯源「这个 `diff_sh` 是哪来的」。

### 1.7 扩展思路

- **统一 `recount`**：抽取 NPC/玩家/比武三份为单一函数 + 少量策略参数（是否含镜像软上限），消除数值分叉。
- **属性来源追溯**：把 `prop` 从「数值字典」升级为「数值+来源列表」`{value, sources:{id:delta}}`，可一键定位某属性的所有贡献者。
- **属性管线（modifier pipeline）**：采用「基础值 → 加法层 → 乘法层 → 上限层」的标准 RPG 管线，替代散落的 `+prop*gj_per/100` 手写公式。
- **设计规范对齐**：规范的四维「进攻/防御各管两维 + 属性对抗」可映射为现有 `str→gj/zj`、`con→max_hp/内力`、`dex→ds`、`int→学练效率`，可通过给 `int` 增加「命中/战意」维度补齐悟性的战斗职能。

## 二、技能系统

### 2.1 数据结构

基础技能对象由 `SKILL` 构造（[skill.js#L4-L11](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L4-L11)），关键字段：

| 字段 | 含义 | 定义处 |
|---|---|---|
| `id` / `name` | 技能标识 | [L5-L6](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L5-L6) |
| `type` | BASE(0)/SKILL(1)/KNOWLEDGE(2) | [const.js#L1-L5](file:///d:/wushen/wushen/WuShenMud/os/const.js#L1-L5) |
| `grade` | 品阶（决定颜色与升级曲线） | [L8](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L8) |
| `can_enables` | 可装备到哪些基本技能 | 详见 [L426-L430](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L426-L430) |
| `pfm` | 绝招字典 | [L402-L412](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L402-L412) |
| `learn_condition` | 学习条件 | [L207-L264](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L207-L264) |

品阶→颜色/描述（[L413-L414](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L413-L414)）：0 基本~6 无上神武，共 7 级。

**玩家技能槽**存在 `this.skills` 映射中，每项结构为：

```js
skills[skid] = { level, exp, enable_skill, addin:[槽], ref:"技能/绝招" }
```

`query_skill` 返回的是「技能等级 + prop 加成」（[chara_skill.js#L3-L6](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L3-L6)）：

```js
query_skill(name, def) { return this.skills[name].level + this.query_prop(name); }
```

即**装备/宝石也能提高技能「有效等级」**，这是技能与属性双向耦合的关键。

### 2.2 学习与条件校验 `do_learn`

[skill.js#L207-L264](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L207-L264)。支持条件键：`skill`（依赖其他武功等级）、`str1/con1/dex1/int1`（先天）、`str/con/dex/int`（先天+后天）、`gender`、及任意 `prop` 键兜底。

- **`int` 未参与学习运算**：学习效率靠 `study_per`，悟性仅作门槛，未形成「悟性→学习速度」的正反馈。
- **`type=SKILL` 且无 `learn_condition` 时**走 `can_enables` 兜底：必须已会对应基本技能（L253-L262）。

### 2.3 装备（enable）系统

**核心概念**：基本技能（force/dodge/parry/unarmed/sword…）是「插槽」，特殊技能是「插件」。`enable_skill(base, skill)`（[chara_skill.js#L117-L148](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L117-L148)）把特殊技能装到基本技能上：

- 先卸掉 `base` 上已有的旧技能（`old_skill.disenable`）；
- 校验 `sp_skill_base.enable(me, base)`；
- 写入 `baseskill.enable_skill` 与 `sp_skill[base]=true`；
- 最后 `init_skill()` + `recount()`。

**`init_skill`**（[L150-L158](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L150-L158)）把「当前生效的技能对象」缓存为快捷字段，供战斗循环零查找使用：

```js
attack_skill  = query_used_skill(query_weapon_type())   // 按武器类型
noweapon_skill= query_used_skill(WEAPON_TYPE.NONE)       // 空手
dodge_skill / parry_skill / force_skill = query_used_skill(...)
on_skillchanged && this.on_skillchanged()               // 通知前端刷新绝招栏
```

**`query_used_skill`**（[L160-L172](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L160-L172)）：若基本技能上装了 `enable_skill`，返回**被装特殊技能的对象**，否则回退到 `WORLD.DEFAULT_SKILLS[名字]`。这就是「基本技能提供动作，特殊技能提供属性/绝招」的解析入口。

### 2.4 属性附加 `attach_prop` / `release_prop`

[skill.js#L65-L107](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L65-L107)。三段属性来源：

1. `query_prop(lv)` —— 常驻属性（学即得）；
2. `query_enable_prop(lv)` —— **装备为某基本技能时才生效**的属性（`me.is_enable_skill(id, item)` 判定）；
3. `query_addin_prop(me, lv)` —— 「进阶槽位」属性（`sk.addin` 数组，源于 `slots`），仅当 `is_enable(me)` 为真。

`attach` 加、`release` 减，二者严格对称，用于「改等级/改装备」时先卸后挂。

`enable`/`disenable`（[L164-L206](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L164-L206)）则只处理 `query_enable_prop` 的**本槽**部分与进阶属性。

### 2.5 经验曲线与升级 `add_exp` / `grade_up`

**升级所需经验**（[L46-L49](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L46-L49)）：

```js
level_exp(lv, me) = (lv + 1) * (grade + 1) * 5
```

**加经验**（[L324-L365](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L324-L365)）：若技能不存在则先建 0 级记录；累加 `exp`；`while(exp >= need_exp)` 循环 `level++`（可连升）；**仅 `level>100` 才累计 `score`**；升级后 `attach_prop` 重挂属性、`recount`、通知前端。

**等级 100 之后的积分**（[L366-L379](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L366-L379)）：`query_score(lv) = (lv-100) * query_one_score()`，特殊技能 `one_score=grade`、基本技能 `=1`——**品阶越高，冲级收益越大**。

**突破转生 `grade_up`**（[L380-L401](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L380-L401)）：要求 `skill.level >= 1000`，`query_needexp`（[L50-L58](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L50-L58)）换算成目标技能初始等级 `sqrt(pot*2/5/(grade+1))`，并把原技能换成目标技能。

### 2.6 绝招 PFM 体系

**PFM 对象**定义在技能的 `pfm` 字典中，`update()` 时统一注入原型与元数据（[L467-L478](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L467-L478)）：

```js
pfm.id = this.id + "/" + key;   pfm.pid = key;
pfm.__proto__ = PERFORM.prototype;   // PERFORM 见 L615-L618
```

**关键字段**：`mp`/`query_mp`（内力消耗）、`distime`/`query_distime`（冷却）、`release_time`/`query_releasetime`（前摇）、`enable_skill`（限定武器/部位）、`use(me,target,lv)`、`check`、`use_type`、`allow_busy`，以及 `query_desc`。

> ⚠️ 大量 `query_mp`/`query_releasetime`/`query_distime`/`query_desc` 由**各技能文件自行覆写**；`SKILL.prototype` 没有提供默认实现（除 `query_name`，[L620-L622](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L620-L622)）。缺失覆写会导致运行时 `undefined is not a function`。

**自动释放**（[auto_combat.js#L84-L133](file:///d:/wushen/wushen/WuShenMud/world/extends/char/auto_combat.js#L84-L133)）：

- `attack_count ||= pfm_rate || 3`，每次 `random(attack_count)!==0` 就跳过 → **平均每 3 次普攻尝试放一次绝招**（简化版「战意」节流）；
- 遍历 `auto_skills`，过滤 `ban_use`、忙乱、冷却未到、内力不足；
- 命中条件后 `use_pfm`，写入 `release_time`（前摇）与 `skill.release_time`（冷却）。

`auto_skills` 由 `init_pfms`（[L134-L165](file:///d:/wushen/wushen/WuShenMud/world/extends/char/auto_combat.js#L134-L165)）按「武器/内功/空手/闪避/招架/暗器」六类基本技能收集。

**玩家侧**：`on_skillchanged`（[user.js#L681-L733](file:///d:/wushen/wushen/WuShenMud/os/char/user.js#L681-L733)）把可用绝招序列化为前端 `perform` 面板；`change_distime`（[skill.js#L624-L647](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L624-L647)）改冷却并通知前端动画。

### 2.7 技能等级上限 `skill_limit`

[chara_skill.js#L87-L99](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L87-L99)：

```js
level1: round((exp*20)^(1/3));  level2: (exp*30)^(1/3); ... level6: (exp*60)^(1/3); 默认 (exp*10)^(1/3)
```

以经验开立方决定可练到的技能等级——成长曲线陡峭（等级增长远慢于经验）。`<100` 经验时统一给 10。

### 2.8 优点

1. **「基本技能=插槽 / 特殊技能=插件」模型清晰**：扩展新武功只需写一个 `SKILL` 文件并声明 `can_enables`，无需改动引擎。
2. **三段式属性来源**（常驻 / 装备限定 / 进阶槽）表达力强，可区分「学了就有」与「装上才有」。
3. **绝招数据完全外置**：冷却、耗内、动作、`use` 全在技能文件，策划可独立调参。
4. **冷却机制双轨**：`temp["pfm/id"]`（玩家，持久冷却）+ `auto_skills[].release_time`（NPC，内存冷却），各取所需。

### 2.9 缺点 / 隐患

1. **绝招方法无基类默认实现**：`query_mp/query_distime/query_desc` 等依赖子类覆写，缺一个就运行时报错，缺乏健壮性。
2. **`grade_up` 依赖 `query_needexp` 但该方法对 `level<=100` 返回 0**（[L50-L58](file:///d:/wushen/wushen/WuShenMud/os/skill/skill.js#L50-L58)），而 `grade_up` 要求 `>=1000`，语义割裂。
3. **`add_exp` 的 score 只在 `level>100` 累计**，与 `query_score` 的 `lv<=100 → 0` 一致，但 `remove_skill` 却用 `baseskill.query_score(skill.level)` 反向扣分（[chara_skill.js#L61](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L61)），若技能升级路径绕过 `add_exp`，分数会漂移。
4. **`query_used_skill` 的副作用**：找不到技能基底时**修改** `skill.enable_skill = null`（[L168](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L168)）——查询函数带写副作用，热更新技能定义后可能静默解绑装备。
5. **`skill_limit` 用 `this.level` 但 `case 6` 与 `default` 公式相同**（[L95-L98](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L95-L98)），冗余分支，且 `level` 未定义时落到 default。
6. **绝招节流过于粗糙**：`attack_count` 逻辑等价「1/3 概率」，无法表达「大招需要蓄力/连招前置」等设计。

### 2.10 扩展思路

- **给 `SKILL.prototype` 补默认实现**（`query_mp` 返回 `this.mp||0` 等），消除子类缺失崩溃。
- **绝招前置/连招**：引入 `combo`/`require_status` 字段，把「1/3 概率」升级为「前置招式或状态触发」，与设计规范的「战意放大器」接轨（战意≥阈值才放大招）。
- **技能品阶与数值缩放解耦**：当前品阶只影响经验曲线与 score；可引入设计规范的「品阶缩放系数」让高阶技能在数值上也有明确杠杆。
- **绝招冷却统一前端**：把玩家 `temp["pfm/id"]` 与 NPC 内存冷却合并为同一抽象，减少 `change_distime` 的双分支。
- **`enable` 关系图校验**：装备切换时校验「插槽唯一性」，避免 `enable_skill` 悬空。

`begin_attack` 关键逻辑：只有当 `type > this.fight_type` 时才升级战斗强度（`1`=打到见血即止、`2`=死斗）；首次进入战斗时 `call_out(auto_attack, random()*gjsd)` **随机延迟首刀**，避免同帧同步攻击。

`end_attack` 的判定链（[L145-L168](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L145-L168)）：

- **比试点到为止（fight_type=1）**：目标血量 `<30%` 即判负，`hp<=0` 强制保到 1；
- **死斗**：`target.hp<=0 && target.die()` 后观测击杀。

`fight_type` 是战斗模式核心开关，被 `can_attack`（[L134-L136](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L134-L136)）、`is_fighting`（[L96-L108](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L96-L108)）、`do_attack` 多处依赖。

### 3.2 攻击循环 `auto_attack`（事件驱动，无主循环）

[auto_combat.js#L7-L58](file:///d:/wushen/wushen/WuShenMud/world/extends/char/auto_combat.js#L7-L58)，用 `call_out` 自调度而非全局心跳：

```
dead → 让目标 end_attack 或 end_fight
无目标 → end_fight
昏迷(is_faint) → call_out(is_faint) 后返回
前摇中(release_time) → call_out(剩余时间) 返回
忙乱(is_busy) → 若 auto_pfm+busy_pfm 尝试放招，否则 call_out(busy) 返回
否则 → do_attack(...)；未命中/未结束 → call_out(gjsd)
```

`gjsd`（攻击间隔毫秒）来自 `recount`：`4000 - prop("gjsd")`，再按 `gjsd_per` 缩减、下限 500 ms（[combat.js#L4-L6](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L4-L6)）。即**基础 4 秒一刀，最快 0.5 秒一刀**。

> 注意：`do_attack` 的返回值若为真则**不再调度下一刀**（`if (!sh || this.end_attack(...))` 的短路），依赖 `end_attack` 返回 `true`（继续）来续期——胜利/死亡则自然停摆。

### 3.3 单次攻击结算 `do_attack`（战斗核心）

[world/extends/char/combat.js#L27-L179](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L27-L179)。完整时序：

**① 前钩子**：`attackskill.on_before_attack` → `force_skill.on_before_attack`（可无条件改 `par`）。

**② 选部位**：`par.part ?? target.query_part()`（[combat.js#L170-L172](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L170-L172)，`CHARACTER_PARTS.random()`，表见 [L224-L240](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L224-L240)：头部 `hert=1.2 crit=10`、四肢 `0.85` 等）。`hert` 是部位伤害倍率，`crit` 是部位暴击加成。

**③ 闪避 / 招架判定**（[L58-L79](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L58-L79)）——**这是与实际设计规范差异最大的地方**：

```js
命中基准 mz = this.mz，目标闪避 ds / 招架 zj
默认：is_dodge = rand()*(ds/2)+ds/2 > mz           // 闪避概率 = clamp( 2*(ds-mz)/ds , 0, 1)
      is_parry = rand()*(zj/2)+zj/2 > mz           // 招架同理
特殊：目标昏迷/攻击者隐身 → 必中不闪不招
      目标 is_rash(破绽) → 必不闪，仅可能招架
      攻击者 is_miss → 必被闪
      目标 is_busy(忙乱) → 只可能被闪，不能被招架
```

> 关键：这里是**线性阈值概率**（`ds≥mz` 时闪避概率可到 100%），而非设计规范的比值概率 `命中/(命中+闪避)`。属性差足够大时会出现「必闪/必中」的极端。

**④ 伤害基础**（[L100-L132](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L100-L132)）：

```
sh = 攻击方 gj (par.gj ?? this.gj)
若招架成功 → sh = 0        // ★ 招架是 100% 免伤，而非规范的「减伤 50%」
若闪避 → sh = 0
否则：
  sh += weapon.do_attack(...)        // 武器/暗器钩子
  sh += attackskill.on_attack(...)   // 武功钩子
  sh *= par.attack_part.hert          // 部位倍率
  sh += sh * prop("add_sh_per")/100    // 最终伤害%
  暴击 → sh *= (150 + prop("add_bjsh_per"))/100
  power_gj（内力攻击）叠加，且空手时才吃 add_sh_per/暴击
```

**暴击判定**（[L21-L26](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L21-L26)）：`rand(100) < bj + part.crit - target.prop("diff_bj")`，其中 `bj = dex/10 + prop("bj_per")`。

**⑤ 受击钩子与伤害落地**（[L133-L141](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L133-L141)）：`target.force_skill.on_force_parry`（内功化解）→ `target.damage(sh, this, par.diff_fy)`。

### 3.4 伤害减免链 `damage`（防御结算）

[world/extends/char/combat.js#L205-L249](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L205-L249)，**这是本项目的「防御链」，对应设计规范的「五层防御」但层数与公式完全不同**：

```
1) par.diff_fy 削防：diff_sh_per -= diff_sh_per*diff_fy/100；fy -= fy*diff_fy/100
2) 攻击者 diff_fy_per（忽视防御）：先扣 diff_sh_per，溢出再扣 fy
3) if diff_sh_per>0: sh = sh - sh*diff_sh_per/100        // 百分比减伤
4) if fy>0: sh = sh/(sh+fy)*sh                           // ★ 防御值平方衰减曲线
5) sh -= prop("diff_sh")                                  // 固定减伤
6) equipment[1].on_defense（衣服钩子）
7) force_skill.on_damage（内功钩子）
8) add_hp(-sh)，记录 damages 统计
```

其中第 4 步 `sh²/(sh+fy)` 是核心防御公式：`fy` 越大衰减越强，但**永不归零**（`fy→∞` 时 `sh→0`，有限值不为 0），设计上是「软减伤」。第 5 步 `diff_sh` 是硬减伤，可把伤害打到 0。

**补充通道**：`damage2`（[L250-L265](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L250-L265)）跳过 fy/减免计算，仅走内功钩子；`damage3`（[L266-L274](file:///d:/wushen/wushen/WuShenMud/world/extends/char/combat.js#L266-L274)）直接 `add_hp(-sh)`。三者语义不同，技能文件里混用。

### 3.6 与设计规范（wuxia-mud-combat）的对照

| 设计规范要素 | 本项目实现 | 差距 |
|---|---|---|
| 五层防御链（命中→招架→护盾→免伤→气血） | 命中闪避→招架→`diff_sh_per`→`fy`平方衰减→`diff_sh`→钩子 | 无「护盾池」独立层，防御链改造为「百分比+曲线+固定」三段 |
| 真气护体护盾池（内力×系数） | 仅 `force_rad` 把内力折入 `max_hp` | 无一次性护盾吸收池，无破盾时点概念 |
| 免伤固定% | `diff_sh_per`（百分比减免）+ `diff_sh`（固定） | 概念相近，但 `diff_sh_per2` 在常规战斗被忽略（见 1.6） |
| 战意放大器（≥12→×1.30） | 无 | 绝招仅靠「1/3 概率」节流，无战意资源 |
| 破绽层数（+8%/层，衰减） | 无 | 无层数衰减系统 |
| 碾压（攻防比≥2→×1.75） | 无 | 只在闪避判定上体现属性差 |
| 概率比值公式 | 线性阈值 `rand()*(ds/2)+ds/2 > mz` | 极端属性差会「必闪/必中」 |
| 招架减伤 50% | 招架 = **100% 免伤** | 招架过强，缺乏代价机制 |
| 品阶缩放系数 | 品阶仅影响经验/score | 数值层面无品阶杠杆 |

> 结论：**本项目是「简化即时制」，设计规范是「完整资源博弈制」**。二者可视为「当前实现」与「目标形态」，扩展思路即朝着规范靠拢。

### 3.7 优点

1. **事件驱动、无全局心跳**：每角色自调度 `call_out`，天然错峰，避免集中计算尖峰。
2. **钩子极其丰富**：`on_before_attack/on_attack/on_attack_over/on_parry/on_force_*` 覆盖战斗全阶段，技能表现力强，武功作者无需改引擎。
3. **`gjsd` 战斗节奏可调**：攻速属性直接决定出招频率，易平衡。
4. **明亮分离**：`do_attack`（进攻）/`damage`（防御）/`force_skill`（内功）职责清晰，便于按武器类型/内功自定义。
5. **比试/死斗双模式**：单开关区分 PvP 点到为止与死斗，社交友好。

### 3.8 缺点 / 隐患

1. **无资源循环**：气血/内力战斗中几乎无自然回复（仅 `dazuo`/`liaoshang`/药物），长战斗靠「内力攻击」硬拼，缺乏设计规范的「每招回内力/精力」节奏。`expend_jingli`（[user.js#L162-L182](file:///d:/wushen/wushen/WuShenMud/world/extends/char/user.js#L162-L182)）虽存在「精力」配额，但战斗循环并未调用。
2. **招架 100% 免伤 + 线性概率**：高 `zj` 角色可近乎无敌；`rand()*(zj/2)+zj/2 > mz` 在 `zj≫mz` 时必招架，缺乏「招架消耗」。
3. **`do_attack` 巨型函数**（150+ 行）：进攻、判定、伤害、表现、回调糅于一体，注册了 8 个钩子，可读性与可测性差；`sh` 被反复覆写，易引入顺序 bug。
4. **`do_attack` 返回值语义重载**：既是「伤害值」又当「是否继续」的判断（`if (!sh || ...)`），`sh=0`（被闪/招架）与「战斗结束」混淆，逻辑脆弱。
5. **`diff_sh_per2` / `diff_sh_per` 双轨遗漏**：常规战斗忽略 `diff_sh_per2`（1.6 节），导致太极神功/易筋经等的「减伤 2」在实战无效。
6. **`end_attack` 与 `auto_attack` 的续期靠返回值耦合**：一旦某技能 `on_attack_over` 返回异常值，可能提前停战。
7. **暴击/部位随机不可控**：`random(4)`、`CHARACTER_PARTS.random()` 无种子、不可回放，调试与数值验证困难（设计规范强调离线可模拟）。
8. **`fight_type` 无上限叠加**：`add_enemy` 无条件 push（[L39-L44](file:///d:/wushen/wushen/WuShenMud/os/char/combat.js#L39-L44)），重复 `begin_attack` 可能让同一敌人多次入列，`query_enemy` 才去重。

### 3.9 扩展思路

- **引入四资源**（气血/内力/精力/战意）：战斗中按「每招回内力 0.5%、精力 1%」，把 `expend_jingli` 真正接进战斗；大招消耗战意。
- **招架改为减伤 50% + 消耗**：把 `par.is_parry → sh=0` 改为 `sh *= 0.5` 并扣除精力，形成攻防博弈。
- **护盾池（真气护体）**：新增 `shield` 字段，受伤先扣护盾，破盾触发 debuff/表现——即设计规范第 3 层。
- **概率改为比值公式**：`命中率 = mz/(mz+ds)`，消除必闪/必中，天然保留弱方「攒战意」空间。
- **品阶缩放**：按设计规范给品阶加数值系数，让高阶武功在「攻/防/内力」上都有明确杠杆。
- **`do_attack` 拆分**：抽出 `roll_hit` / `roll_parry` / `calc_damage` / `apply_damage`，便于单测与离线模拟。
- **回合可回放**：记录 `par` + 随机种子，支持战斗日志回放与数值回归测试。

## 四、状态系统

> 「状态」在本项目含两套独立概念：**(A) `status` 数组**（buff/debuff，附属性与标志位）与 **(B) `state` 对象**（打坐/疗伤等需持续进行的行动状态机）。二者互不相同，切勿混淆。

### 4.1 A：Buff 数据结构与字段

`this.status` 是对象数组，每项字段（综合 [chara_skill.js#L182-L259](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L182-L259) 与 [L353-L396](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L353-L396)）：

| 字段 | 含义 |
|---|---|
| `id` / `name` / `desc` | 标识与展示 |
| `duration` / `duration_count` | 单次时长 / 需触发的次数（用于 `on_interval`） |
| `handler` | `call_out` 定时器句柄 |
| `start_time` | 起始时间（前端画进度条） |
| `prop` | 附加属性字典（叠加时按 `count` 循环） |
| `override` | 0=不覆盖 / 1=可叠加 / 2=覆盖替换 |
| `count` / `max_count` | 当前/最大层数（默认 10） |
| `downside` | 负面状态标记（抵抗/清理用） |
| `only_combat` | 战斗结束即清 |
| `is_busy/is_faint/is_miss/is_rash/is_shadow` | 控制标志位 |
| `ig_control` | 免控标记 |
| `on_interval / on_attach / on_expire` | 周期/生效/失效回调 |
| `no_diff` | 免于负面抵抗 |

### 4.2 施加 `add_status`

[chara_skill.js#L182-L259](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L182-L259) 是状态系统的总入口，流程：

1. 死亡/缺省初始化（`count=1`, `max_count=10`, `start_time=Date.now()`）；
2. **免控判定**：`ig_control` 且非 `no_diff` → 忙乱/昏迷/必中被免疫（L194-L198）；
3. **负面抵抗**：`downside+duration` 时按 `diff_downside_per` 缩短（L199-L205）；
4. **忙乱抵抗/延长**：`is_busy` 时按施加者 `busy/busy_per` 延长、按受者 `diff_busy/diff_busy_per` 缩短（L206-L216）；
5. **同 id 合并**（L217-L252）：
   - `override=0`：直接忽略；
   - `override=1`：`count += buff.count`（受 `max_count` 限），刷新计时，`status_changed("refresh")`；
   - `override=2`：先移除旧的（触发 `change_buff(false)`），再换新 buff，重挂属性与计时；
6. 否则 `call_out(remove_status, duration)` 入列并 `change_buff(true)`。

### 4.3 生效/失效 `change_buff`

[chara_skill.js#L353-L396](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L353-L396)，是 buff 与「属性系统 / 控制标志」的桥：

- **加**：按 `count` 循环 `change_prop(buff.prop, true)` → `recount()`；设置 `ig_control/is_busy/is_miss/is_rash/is_shadow/is_faint` 字段为 `duration`（**注意：存的是「时长」而非布尔**）；播 `start_msg`。
- **减**：按 `count` 循环反向 `change_prop`；清标志位；播 `finish_msg`；`remove_temp(buff.id)`。

> ⚠️ 标志位存的是**毫秒时长**（如 `this.is_busy = buff.duration`），而 `check_command`/`do_attack` 却按布尔使用（`if (this.is_busy)`）。`duration` 是正整数 → 长时间内真值恒成立，实际等同布尔，但**语义混乱**；且若 `duration` 为 0（无限 buff），标志位反而为假。

### 4.4 到期与周期 `remove_status`

[chara_skill.js#L505-L555](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L505-L555)：

- 有 `on_interval`：`over_count++`，回调可返回 `false` 强制设定 `duration_count`，未到次数则重排 `call_out` 返回；
- `override===1` 且 `count>1`：`count--`，重排计时，`status_changed("refresh")`；
- 否则：`status_changed("remove")` + `_splice_status` 移除。

`_splice_status`（[L556-L565](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L556-L565)）通过对象引用定位下标再 splice，规避了「定时器回调时下标已漂移」的问题——这是正确的防御性设计。

### 4.7 B：`state` 行动状态机（打坐/疗伤等）

`state` 对象（[user.js#L522-L551](file:///d:/wushen/wushen/WuShenMud/os/char/user.js#L522-L551)）字段：`title/rate/heat_count/on_enter/on_stop/no_move/desc/commands`。

### 4.8 优点

1. **单入口 `add_status` + 三种 override 语义**：覆盖「唯一刷新/可叠层/替换重生」三大常见 buff 模式，表达力足够。
2. **定时器 + `start_time` 双轨**：服务端 `call_out` 到期、前端按 `overtime` 画进度条，两端解耦。
3. **抵抗维度丰富**：`diff_downside_per`（负面抵抗）、`diff_busy/busy_per`（忙乱博弈）、`ig_control`（免控），形成「控制类 buff」的完整对抗。
4. **`_splice_status` 引用定位**：正确处理了定时器回调与数组下标漂移的经典陷阱。
5. **周期伤害用 `on_interval`**：如化骨绵掌每 3 秒毒发（[huagumianzhang.js#L39-L54](file:///d:/wushen/wushen/WuShenMud/world/skill/unarmed/huagumianzhang.js#L39-L54)），机制干净。

### 4.9 缺点 / 隐患

1. **标志位语义混乱**：`is_busy` 等存「毫秒时长」却按布尔用（4.3 节），`duration=0` 的常驻控制会失效。
2. **`count` 与 `prop` 叠加可能不同步**：`change_buff` 按 `count` 循环叠加属性，但 `remove_status` 首次进入 `override===1` 分支时先 `change_buff(item,false,1)` 再 `count--`（[L530-L534](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L530-L534)），多层叠加的减属性份数与 `count` 是否严格配平，需逐场景核对（`override=2` 的 refresh 路径不会减 `count`）。
3. **`remove_status` 对 `override!==1` 直接移除**（[L546-L550](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L546-L550)），忽略 `count`——`override=2` 的 buff 若 `count>1` 会被一次性删掉。
4. **`clear_status` 用正序 for 且 splice? 否**：它改用 `status.length=0`（[L342](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L342)），安全；但 `clear_downside` 用正序 `splice(i,1); i--`（[L271-L272](file:///d:/wushen/wushen/WuShenMud/os/char/chara_skill.js#L271-L272)），虽正确但风格与其它清理族（倒序）不一致。
5. **`change_buff(false, item.count)` 与 `(false,1)` 混用**（覆盖 vs 层数路径），减属性份数依赖调用点正确，易错。
6. **`on_interval` 回调捕获变量**：如化骨绵掌 `on_interval` 闭包捕获 `lv`（[huagumianzhang.js#L36-L54](file:///d:/wushen/wushen/WuShenMud/world/skill/unarmed/huagumianzhang.js#L36-L54)）——buff 存的是**函数引用**，该函数无法被序列化存档，**玩家下线/重启后周期伤害 buff 会丢失回调，属性仍在但毒不发作**。
7. **同一 `id` 复用**：`force`/`weapon`/`bikou` 等 id 被多处技能复用为「唯一 buff 槽」（如 [taijishengong.js#L39-L55](file:///d:/wushen/wushen/WuShenMud/world/skill/wudang/taijishengong.js#L39-L55) 用 `id:"force"`），不同技能争抢同一 id 会互相覆盖。
8. **`notify_status`/`appdend_status`/`status_changed` 三段 JSON 手拼**：字符串拼接易漏引号，且三处逻辑几乎重复（`duration`/`overtime`/`count`/`downside` 渲染各写一遍），维护成本高。

### 4.10 扩展思路

- **标志位布尔化**：`is_busy` 等改存布尔 + 单独 `busy_until` 时间戳，消除语义歧义。
- **buff 定义与实例分离**：把 `on_interval` 等函数改为「id → 回调注册表」查表，使 buff 实例**可序列化**（修复 4.9-6 的下线丢失）。
- **统一的 buff 描述器（descriptor）**：`{id, duration, count, override, flags, propFrom, onTick}`，属性计算用 `propFrom(state)` 惰性求值，避免按 `count` 循环乘加的份数错配。
- **控制类 buff 独立命名空间**：`busy:faint:...` 前缀，避免多技能争抢同一 id。
- **状态 `state` 与 `status` 统一抽象**：二者都是「持续行为 + 计时 + 回调」，可抽公共基类 `TimedEffect`，减少双套逻辑。
- **对齐设计规范的破绽/战意**：把「破绽层数、战意点数」实现为 `override=1` 的可叠层 buff（现成机制即可复用），`on_interval` 做衰减。
