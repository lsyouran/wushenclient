# 33 · 开发规范

> **本册回答"怎么在这里改一次代码"。** 它不回答"这个名字该叫什么 / 这道闸门守什么 / 这条断言为什么这么写" ——
> 那些各有原册：名字查 **32 册**｜命名法 · 禁止清单 · 闸门表 · FG 家族查 **24 册**｜
> 测试分层与验证内环查 **30 册**｜"这一批到底改了什么"查 **26 册**。
>
> 本册只写三件**别处没有**的事：**动手前的查证顺序**（§2）· **抄 wushen 的判据**（§3）· **收工的判据**（§7）。

## 33.0 为什么需要这一册

前 67 个批次的返工，根因收敛成三条 —— 都不是"能力不够"，而是**没有共同动作**：

| # | 根因 | 表现 | 已经付过的学费 |
|---|---|---|---|
| 1 | **没有单源**（同一事实写两处） | 两份清单各自演化，谁也不改谁 | `PROP` 别名层（26 册 §67.8）· `recount` 两份算法（**29 册 §29.2 末**）· 别名表"一份真相 + 三处镜像"（**FG-20**，24 册 §5.3） |
| 2 | **抄 wushen 的形状，不抄它的语义** | 数字抄对了、名字没换；或名字对了、**它守的前提早就不在** | 13 个方向短写错位（24 册 §8 #25）· `if (obj.hp)` 被当成唯一活体判据（**26 册 §41**：wushen 其实有两条判据，被偷换成一条） |
| 3 | **没有"什么时候算完"的定义** | "能跑"当完事；闸门绿了当守住 | FG-1…FG-23 整族 · 本批 3 条假绿（26 册 §67.5） |

⇒ 对策与下文三章一一对应：**单源（§1）· 移植判据（§3）· 收工判据（§7）**。

## 33.1 三条不可协商

| # | 规则 | 自问的判据 | 谁在守 | 违反的后果（实测过） |
|---|---|---|---|---|
| A | **一条事实只有一处** | 我这段是不是把某册/某表的内容抄了一份？ | 人（闸门只能守形状） | 别名层让 G3 的**输入归零**、日志仍"✅ 通过"（FG-7） |
| B | **一套名字**（代码 / 数据 / 中文 / 技能 id 四层，不并存两套别名） | 同一个东西，我是不是又给它起了一个新名？ | G3 / G3.G / G5 | 拼音与英文并存 → 写文档时两边对不上（§67 的起因） |
| C | **结论必须能取证**（实测 / 断言 / 闸门，三选一） | 我这句话的"怎么证明"是哪一条？ | 人 + 30 册 §5 | "✅ 已清偿"本身是快照，grep 生产调用点后是零（26 册 §55） |

★ C 的操作版：**注释里不写没验过的话**（§4 末）。

## 33.2 动手前 10 分钟（顺序不能反）

五步，按顺序走，前一步没结论不进下一步：

| 步 | 做什么 | 具体命令 / 落点 |
|---|---|---|
| 1 | **查名字** | 32 册 §32.0 三条查法（属性键 / 技能 id / 内容 id）→ 不认识的名字先查它 |
| 2 | **查这片踩过什么** | `grep -rn "<关键词>" docs/26-代码审查记录.md` + `docs/24` §4 禁止清单 |
| 3 | **查数值口径** | 要动公式/容量/上限 ⇒ 29 册（尤其"已知偏离与裁定清单"，**别把有意偏离顺手统一掉**） |
| 4 | **查 wushen 原文** | 必须落到 `文件:行号`；只有"我记得它是这样"不算 |
| 5 | **三个自问** | ①这东西的单源在哪？②谁在守它（哪道闸门/哪条测试）？③我顺手要改的那处，是不是**有意偏离**？ |

★★ **第 5 步的 ③ 是最贵的**：本项目有**成组的有意偏离**（**29 册 §29.4** 的 4 条数值裁定 ·
**24 册 §7** 的 D1–D4 · **26 册 §21.4** 的 10 处前端偏离），"顺手统一"会把它们一起改回原作的 bug。

★ **第 1 步的反面教材**：批量替换属性键时，`dazuo` 在**别处也是合法标识符**（指令 id 打坐），
29 处被误改（26 册 §67.3）。**查名字要查"这个名字在别处是什么"**，不只是"它在这里是什么"。

## 33.3 抄 wushen 的五条判据（★ 本册核心）

项目不是"照抄一遍"，但也不是"重写一遍"。每抄一处，过这五条：

### ① 数字照抄，名字换成本项目口径

系数、阈值、顺序、文案**一律照抄**（那是原作调过的），但**键名 / 标识符**必须换成本项目的口径：

```ts
// wushen:  prop: { gj: lv }
// 本项目:  prop: { attack: lv }        ← 数字同一个 lv，键换英文
```

★ 反例：`max_hp` 的 `con` 项曾经"看起来更合理"地除了 10，后来**裁定照抄**（29 册 §29.4 偏离①）。
**"更合理"不是理由，能说出原作为什么那样才行。**

### ② 分开「思想」与「它那个时代的补丁」

wushen 是 ES5 时代的代码，很多形状是**当时的限制逼出来的**，照搬要交税（见 24 册 §8 的缺陷清单）：

| 属于**思想**（要抄） | 属于**时代补丁**（不抄） |
|---|---|
| `if (!lv) return`（0 级技能不贡献属性） | 4 份 `user.js` 副本、`util.inherits` + `__proto__` 双机制 |
| `release_prop` / `attach_prop` 的记账式增减 | 目录序加载、全局裸变量 |
| `create_by_odds` 的掉落语义 | 手工拼 JSON、`WORLD.OBJ_STROE` 拼错的索引名 |

**判据**：这段代码的存在理由如果只是"当年 JS 没有 X"，就换成本项目的 X，**但要保住它的行为**。

### ③ 快照 ≠ 现状（原作注释也会撒谎）

wushen 的注释与文档写的东西，**必须拿执行路径复核**。
实测：`docs/wushen/` 里说消息队列不回收，`message.js:46-48` 其实在回收（FG-11 同族）。
⇒ **引用 wushen 一律带目录 + 行号**（24 册 §5.5），"我记得"、"应该是"都不能进注释。

### ④ 抄它的判断之前，先问「它当时守的前提还在吗」

这是最容易漏的一条，因为它抄出来**能跑、看着对**：

| wushen 的写法 | 它当时的前提 | 本项目的正确做法 |
|---|---|---|
| `if (obj.hp)` 判活体 | 当年只有 NPC 有 `hp` | 用**结构判据**（持不持 `def`），不许 `instanceof Npc`（会造 ESM 循环）。★ 注意原作其实有**两条**判据，"进出者必须是活体"这一条差点被漏（**26 册 §41**） |
| `doors[]` 与 `doors_short[]` 两个数组按下标对齐 | 手写常量、没人校验 | **别抄这个形状**，短写方向错位 13 个（24 册 §8 #25） |
| `dodge` / `parry` 兼作技能 id 与槽名 | 原作没有命名空间概念 | 数值侧改名 `evasion` / `deflect`（G3.G 守） |

### ⑤ 只抄数据形状，不抄运行时耦合

内容层（`world/**`）能抄的是 **def 的字面量结构**；
不能抄的是 require 循环、全局单例、"加载顺序决定行为"。
本项目的边界由 **G13** 机械守（`world/**` 不许直连 `server/engine/**`，只许 `@shared/**` 与 `server/world/**`）。

### ★ 每抄一处的记账格式

在 **26 册**该批次里留一行，**这是唯一被接受的"我抄过它"的凭据**：

```
wushen `world/cmd/action/go.js:50-58`  → 照抄语义（出口→满员→on_leave），不抄数组对齐形状
wushen `os/skill/skill.js:65`          → 照抄 `if (!lv) return`；本项目落点 `skill.ts` 的 `st.level === 0`
```

★ 没有这一行 = **无法区分"有意偏离"与"抄漏了"**，下一批的人会把两边又改回不一致。

## 33.4 写代码（只列会翻车的，细则在 24 册）

| 场景 | 规则 | 守它的东西 |
|---|---|---|
| 属性键 | 裸字面量核心键（`prop: { attack: 20 }`）；扩展键必须 `registerExtProp` 登记 | G3.A / G3.B / G3.D |
| 新名字 / 新目录 | 先查**保留字**（`RESERVED_AREAS` 含全部 `KINDS`） | 24 册 §1.6、32 册 §32.10 |
| 让"漏一支就编译失败" | **判别联合 + `switch` 无 `default` + `const x: never = r`** | 类型系统（先证它会红再撤） |
| 对外错误 | 走 `ERROR_CODES`；**不许伪造成功的返回值** | 24 册 §4 #6 |
| 不可信输入 | 数组 / `NaN` / 负数 / 超长**都要显式挡**（`Number.isFinite` 不够） | 26 册 §25 批 |
| `catch` | **不许 catch-all 把内容层的错翻译成"过不去"** | 26 册 §23 |
| 路径 | 由 `import.meta.url` 求根；**禁** `process.cwd()`、禁硬编码 `newmud` | G12 |
| 退出码（工具） | 用 `lib.mjs` 的 `EXIT_*`，禁裸数字；闸门入口装 `installCrashGuard` | G6 R6.7 / R6.11 |

★ **注释 = 断言**（铁律 5）。三条禁令：
1. 不写"已实现 / 已接通"，除非有**生产调用点**（grep 过）；
2. 引用必须带**册号 + 节号**（`26 册 §67.5`）；引用 wushen 必须带**目录 + 行号**；
3. 注释里**教人怎么写**的示例，本身必须是**当前合法**的写法 ——
   §67 之后就踩过：6 处注释还在教 `{ prop: { gj: 5 } }`，照抄直接被闸门判红（26 册 §67.9）。

## 33.5 写测试（方法在 30 册，这里只留判据）

| 判据 | 说明 |
|---|---|
| **先红后绿** | 先写会红的用例并**实证**它红，再改实现；红必须是**行为红**，不是编译红 |
| **红的理由要对** | 只红"该红的那几条"；红在别处说明你碰坏了东西 |
| **对照组** | "一律拒绝"也能让"拒绝"那条全绿 ⇒ 正常路径必须有一条**放行**的对照 |
| **哨兵值** | 写"不该改 X"时先问：**我什么都不做，这条也绿吗？**（是 ⇒ 这条没区分性） |
| **别只测 happy path** | 缺省分支 / 错误路径 / 边界值都要有 |
| **别用合成夹具替代真内容** | 夹具会掩盖"内容没登记 / 命令没进表"（30 册 §6） |

★★ **本批新增的第 5 种假绿（记进脑子）**：**改了名字之后，样本里那个名字从"非法"变成"合法"** ——
`patchFile` 成功、`before` 是 PASS、`after` 还是 PASS，表现为**假绿**而不是报错（26 册 §67.5）。
⇒ **改名批次必须逐个重看样本里那个名字现在还算不算违规。**

## 33.6 一个批次的标准流程

顺序不能换 —— 每一步都为下一步**缩小搜索空间**：

| 步 | 动作 | 为什么是这个位置 |
|---|---|---|
| 1 | **立题**：一句话说清"这批只做什么" | 混批会让 26 册的记录失去检索价值 |
| 2 | **单源**：改定义处，不改消费处 | 改定义，编译器会替你列出所有消费点 |
| 3 | **编译器带路**：`tsc` 把断裂清到 0 | 比 grep 可靠（§67 一次列出 85 处断裂，无需人肉找） |
| 4 | **闸门**：跑 `run-all`，按报错收敛 | 结构问题在这里一次性暴露 |
| 5 | **样本**：改/加变异样本，`mutation --only` 先验，再全量 | 闸门改了不同步样本 = 元闸门当场变红 |
| 6 | **文档**：26 册记一节 + 24 册 §5.5 的七项回写 | 记录面漏了，下一批的人找不到依据 |

★ **为什么不是"先写文档"**：文档要写"实测到了什么"，先写就变成"计划"，而计划会被当成事实（FG-9/FG-10 同族）。
★ **什么时候可以破例**：只有一种 —— **闸门先建、让它在实现前红一次**。
建 32 册时就是这么做的：先在 4 处注释里引用 `docs/32`，让 G15 拦住，再建册（26 册 §67.7）。

### 6.1 分批纪律

- **一批一个主题**。顺手发现的问题**记下来，不顺手改**（除非它挡住这一批）。
- 挡路的那种，**必须写进 26 册的"顺带"**，否则下一批会以为它是自己变出来的。
- ★ 一个批次里**不要同时动**：闸门 + 大改名 + 前端（三类变更的失败信号会互相掩盖）。

## 33.7 收工判据（四条问，全绿才算完）

| # | 问 | 不合格的样子 |
|---|---|---|
| **Q1** | 内环绿了吗？（`tsc` ×2 → `vitest` → `run-all` → 该跑 `mutation` 就跑全量） | 拿上一批的绿当本批证据（30 册 §3.1：**动了就作废**） |
| **Q2** | 该红的地方**还能红**吗？ | 闸门全绿，但样本锚点已被重构挪走（SKL.1 假绿，26 册 §55） |
| **Q3** | 注释还**真的**吗？（尤其"已实现 / 已接通"） | 注释说 A，代码做 B；或注释教了一个已经非法的写法 |
| **Q4** | 记录面齐了吗？（24 册 §5.5 的七项） | 只更新了自己那一册，索引面 / 邻册 / README 全是旧的 |

★ **Q1 的取证纪律**（三次踩过，写死）：
1. **不许带 `--only`** —— 脚本会自己声明"这不是全量结论"；
2. **不许拿管道退出码当 `EXIT`** —— `node x | tail` 的退出码是 `tail` 的，必须重定向落盘再 `echo $?`；
3. **长任务别 `| head` / `| grep`** —— SIGPIPE 会中断子进程（30 册 §3.3）。

★★ **"机检报 N 条、我改了 N 条"是抽样，不是收工**（铁律 1）：
还要问"这个形状有没有**我看不见的写法**"。§67 的教训：`actionchange` 这种名字在代码里根本没有，
因为真实帧叫 `addAction`/`removeAction` —— **照着一份清单改，改的是清单，不是真相**。

## 33.8 改名 / 重命名专项（踩过两次，单独成节）

改名是**唯一一类"编译器帮不全忙"**的改动，因为它会同时穿过四个命名空间（32 册 §32.1）。

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | **确认改的是哪一层** | ①代码名 ②数据键 ③中文 ④技能 id/装配槽 —— 一层一层过，别跨层批替换 |
| 2 | **先改名，不先加别名** | 加别名层 = 留下两套名字，代价不是零（26 册 §67.8） |
| 3 | **旧名怎么办** | 需要兼容就做成**冻结的对照表**（`LEGACY_PINYIN_KEYS`），**只用于报错文案**，不做运行时回退 |
| 4 | **全仓 grep 新名** | `grep -rn "<新名>" tests/ world/ server/` —— 本批就是这么发现 `dazuo` 误伤的 29 处 |
| 5 | **重看变异样本** | 样本里那个名字**现在还算不算违规**？变了就换样本（§33.5 第 5 种假绿） |
| 6 | **重跑全量** | 改名 = 动源码 ⇒ 内环全量 + `gate:mutation` 全量 |

★★ **grep 会命中注释**（实测）：抓"指令 id 清单"时用
`grep -oP "defineCommand\('\K[^']+"`，把注释里"`defineCommand('skill/learn')` 会抛错"这句也抓了，
凭空造出两条不存在的 id（26 册 §67.10）。⇒ **核清单加 `grep -v '^\s*\*'`，或以 `ls` 的目录为准。**

★ **别把旧名表当禁用名单**：`per` / `busy` / `dazuo` / `score` 在别处都是**合法标识符**
（`dazuo` 是指令 id，`per` 是派生后缀）。旧名表只管"数据键"这一层。

## 33.9 红牌清单（一票否决，不讨论）

| # | 红牌 | 为什么是红牌 |
|---:|---|---|
| 1 | 先改实现，后补测试 | 没有证据；测试会写成"实现就是这样" |
| 2 | 把 `SKIP` 当通过 | 闸门没跑起来 ≠ 没违规（铁律 3） |
| 3 | 带 `--only` 去取证 | 输出自己写着"不是全量结论" |
| 4 | 拿管道退出码当 `EXIT` | 你测的是 `tail`，不是闸门 |
| 5 | 断言里写"没调用某函数" | 换个实现就假绿；要锚**结果里的坏状态** |
| 6 | 放宽超时 / 删断言来消红 | 会把真回归一起变成绿（30 册 §4） |
| 7 | 同一事实写第二份 | 两份必然分家，且**没有闸门能发现**（00 册 §4） |
| 8 | 闸门规则不带 `dirs` | 扫描范围与判定范围取两处 ⇒ 交集空 = 永远绿（FG-7） |
| 9 | 注释里写没验过的"已实现" | 注释是断言，假注释比没注释更贵 |
| 10 | 改样本时假设"那个名字还非法" | 假绿，且**不报错**（§33.5） |
| 11 | 只测 happy path | 缺省分支与错误路径才是真 bug 的家 |
| 12 | 把"更合理"当理由改数值 | 成组的有意偏离（29 册 §29.4 四条 / 24 册 §7 的 D1–D4 / 26 册 §21.4 十处）会被一起改回原作的 bug |
| 13 | 写**全称否定**却不带扫描面（"一处都没有"） | 全称否定**被证伪的成本最低**，所以最该限定范围。2026-10-19 实测：G17 头部写「`export * from` / `export default` 当前一处都没有」，其实 `.ts` 面有 **4 处** —— 只是闸门扫不到。**把"我看不见"写成"不存在"**（26 册 §71.6） |
| 14 | 把**会变的数**抄进文档（尤其标"现值"） | G16 的覆盖数**包含文档自身**：写一次就变一次（同日 `825 → 827 → 830`）。**能算的数只写"怎么取"**，不写值（26 册 §71.4） |
| 15 | 给**一次性报告**贴"现值"标签 | 它不会自我更新。`_roadmap-还差多少-2026-10-16.md` 的"现值"与同日实际差了 **5 个批次**（48/1021/8/93 vs 49/1106/10/109） |

## 33.10 机器守得住的 / 只能靠人的（诚实边界）

规范不是替代闸门，而是**说清闸门没守的那部分要你自己守**：

| 闸门守得住（结构） | 只有人能守（意图） |
|---|---|
| 协议发送点 ↔ 声明 ↔ 台账（G2） | "这个包该不该存在" |
| 属性键在允许集内（G3） | "这个属性该不该这么命名" |
| 命名空间隔离（G3.G / G5） | "这个功能该不该属于这个命名空间" |
| 禁硬编码路径 / 依赖方向（G12 / G13） | "这层抽象该不该加" |
| 文档册号存在（G15）；**绑定式** `NN 册 §X` 的节号存在（G16）；00 册 §2 的册清单与磁盘册文件一致（G16.5） | "这个引用指的那一节对不对**题**"；"裸 `§X` 指的是哪一册"（G16 刻意不判，见 24 册 §5.1）；"索引表里那一行描述得对不对" |
| `export` 有没有外部消费者（G17：死代码 / 假契约） | "这个模块**应该**对外暴露什么" —— 闸门只知道"没人用"，不知道"该不该有人用" |
| 标识字典的**标记块内**与代码枚举逐字一致（G18，**九组全部建块**） | "**新增的标识该不该进字典**"、"块外那段解释写得对不对"、"人写表漏了一行没有" —— 闸门只比对块内那份**名单**（§32.13），**块外的人写表仍需人守**（主动选择，见 26 册 §71.8.5） |
| 每条闸门规则**真的会红**（`gate:mutation`） | "红得对不对"（元闸门只证会红） |

★ **闸门全绿 ≠ 改对了**。本项目的 FG 家族全部是在"闸门绿"的状态下产生的。

★★ **"再加一道闸门"不是免费的**（26 册 §71.8.2 的四条实证）。加之前先过**五条**，
**缺一条就别加**，改成"文档纪律 + 人工 checklist"：

| # | 判据 | 反例（本仓） |
|---|---|---|
| ① | **有单源** —— 能机械读出事实 | —— |
| ② | **会漂** —— 有人会改一端忘另一端 | —— |
| ③ | **有人依赖** —— 错了会真的出事 | —— |
| ④ | **判据可落"位置"** —— 不会因为"文档里讨论一个不存在的 id"就假红 | G16 若判裸 `§X`：实测 **80/107 假红** |
| ⑤ | **能造出"必然违规"的样本** | G10/G11 缺对象 ⇒ 造不出 ⇒ 至今不建 |

★ 缺 ① 或 ② ⇒ 加了也是**死规则**（G3.F 形态：对象没了，日志还是绿的）。
★ 缺 ④ ⇒ **假红训练人忽略报警**，比没有闸门更糟。
★ 缺 ⑤ ⇒ 这条规则**从来没被证明过会红**（24 册铁律 4）。
★ 成本也要算：每条规则配 1 条样本，全量 mutation 是 **O(规则数)** 的分钟级开销 ——
样本涨到让人"这轮不跑了吧"，等于所有闸门同时失效。
★ 反过来说：**凡是能用闸门守的，就别写进规范让人记** —— 记忆会漂，闸门不会（这是这个项目的立身之本）。
