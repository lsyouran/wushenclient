# 同日 · M2 的第一版修法是**错的**（冒烟才抓到）

冒烟 `tools/start.mjs --port 8123` 起第二个实例验证 EADDRINUSE 路径 —— **仍挂死（EXIT=124）**。
- 第一版只给 `owner === undefined` 分支的 `wss.on('error')` 挂了监听，**注册太晚**：
  `new WebSocketServer({ port })` **构造时就 listen**，`'error'` 可能比 Promise 执行器还早。
- 更深一层（读 `node_modules/ws/lib/websocket-server.js`）：wuself 自建的 http server 的 `'error'`
  会**转发**到 `wss.emit('error')`；而 EventEmitter 的 `'error'` 若**无人接** ⇒ 直接 `uncaughtException`，
  与 Promise 是否 settle 无关。⇒ 真凶是"wss 上没挂监听器"，不是"Promise 缺 reject"。
- 正确修法：**构造 wss 之后立刻**挂 `wss.on('error')`，指向一个稍后填好的 `rejectFn`（`listen` 异步 ⇒ `rejectFn` 一定先就绪）。
- 复验：第二个实例 **EXIT=1 + "启动失败：EADDRINUSE"**（干净退出，不再挂死）。
- ★ **教训：错误路径的修法不能只看静态代码 —— 端口占用这种分支必须真起第二个进程才证得了。**
  （与铁律一致：fix-before-assert，静态推理不算证。）
