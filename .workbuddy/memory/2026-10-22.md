### 四条可复用判据（★ 都是这一轮才想清的）
1. **CSS 里"布局/色相"可以抄，"控件质感"必须按目标设备重推**。判据是"输入设备变了之后，这个视觉信号还成不成立"。
2. **"居中"是两层的事**：内容在容器内居中 + 容器自身撑满。只做前一层时短文字按钮看起来完全正常，
   **只有容器被拉宽才露馅** ⇒ "我看截图挺居中"不是判据。
3. **"尺寸只有一个来源"不是洁癖**：注释写"与 X 同一套尺寸"而两处代码是 40/44，两句话都成立 ——
   Kotlin 里没有东西把"同一套"变成可执行约束。**注释不是断言，除非有闸门读它**。
4. **生成图的问题要在 prompt 里解决，别在下游写补偿算法**。这一轮下游修图连踩四个坑：
   水印在像素里 / 背景径向渐变（主体暗部比背景亮部还暗，任何阈值都分不开）/
   `ImageDraw.floodfill` 的容差参数同时管"传播"和"要不要动手"（差 ≤ thresh 直接 return）/
   自写 BFS 反过来把衣袍整个吃掉（91% 像素误判）。
   ⇒ 最终解法是把"背景纯黑无渐变 + 衣袍比背景亮"写进 prompt。

### 操作坑

- 自适应图标安全区是 **108dp 里那个 66dp 的圆（61%）**，不是 72dp 那个。
- 未用 import 的自动判据不能只写一套正则：扩展函数（`Modifier.fillMaxWidth`）会被"排除点前缀"的
  lookbehind 全部误报 ⇒ 整页假红。要允许点前缀，代价是 `getValue`/`setValue` 变成已知假红。

## 安卓端视觉重构（26 册 §92）：用户批"割裂/丑" → 收成两层

用户原话：最上方个人信息黑色、中间地图与 npc 灰褐灰棕分不清、日志区黑底绿字、下方聊天又是别的颜色、按钮与文字布局也丑。

### 根因（不是某块丑，是"分层的依据"不是一套）
主屏一屏同时 **6 种填充灰**：`#000` / `#111` / `#1A1A1A` / `#222` / `#2A2A28` / `#898989`，
彼此只差 1~2 个亮度级 ⇒ 肉眼分不出层次（割裂）却明显不属于同一套（丑）。
26 个颜色 token 里 **11 个是自造色**，无 wushen 出处。

### wushen 的答案（§92.2.1 逐条核过 `style.css`）
`.container` 五个区块**一律不刷底色**，只用一条 `--hair: #343434` 发丝线分隔；
全屏唯一有底色的常驻块是 `.state-bar`（`#111`）；`.dialog` 是 `#000` 底 + `#343434` 边 + `#222` 头脚带。
⇒ **wushen 层级只有四档：`#000` 面 / `#111` 凹 / `#222` 带 / `#343434` 线。**

### ★★ 本轮最关键的发现：wushen 有**两族**可点皮肤，§91 退错了对象
- `.tool-item`（`style.css:885`）= `#808080` **实心底** + `#111` 深字 + 700 粗体 + 35×35 方块
  ⇒ §91 退掉的是这一族，退对了（搬到纯黑就是一屏发光亮片）
- `.act-item` / `.pfm-item` / `.chip`（`:711-734`）= `background: var(--bg)`（**#000 黑底**）
  + `1px solid var(--line)`（`#808080`）+ `color: var(--dim)` + `border-radius: 4px`
  ⇒ **这一族才是"黑底上的一排动作"的正解**，§91 没区分两族，把两族一起否了
⇒ 判据：wushen 里**常驻功能入口**（图标方块工具条）不该搬；**当前能做的事**（出口/动作/面板命令）照抄。

### §94 安卓布局塌陷订正（真机截图 → 一个 fillMaxWidth → 五个文件）

- **布局**：地图从 §93 的底部卡片改回 **房名行下方就地展开**（用户改判，§93.2.3 已标取代）；出口/动作栏/改视图键 `dense`；删不可拖的假拖拽条（`DragBar*` 同批删）。
