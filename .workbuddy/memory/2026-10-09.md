### 关键事实（供后续会话直接引用）

- 双进程：`web.js`(Express :8088) + `main.js`(自研 WS :31300)，通过 SQLite + Cookie 票据间接协作，无 IPC。
- 规模：`os/` 9,716 行 · `src/` 11,261 行 · `world/` 926 文件 39,086 行 · `api/` 1,163 行。
- 协议核心：服务端手工拼 JS 字面量字符串（非 JSON.stringify），存在无引号 key 与单引号两种风格；前端用 `new Function("return "+data)` 解析（RCE 风险）。
- 三大协议抽象值得抄：① `dialog` 通用容器（一个 type 打通 23 个面板）② `cmds` 命令条 ③ 三视角文案 `$N/$n/$P/$w/$l`。
- 前端无框架：Vite 8 + jQuery 4 + 模板字符串；index.html 仅 13 行，DOM 全 JS 生成；`Process[data.type]` 一行分发 34 个包类型。
- 战斗不在全局心跳，是每角色一条 setTimeout 自递归链（周期 `gjsd`）。
- `world/` 全部 926 文件零 `module.exports`，靠 `vm.compileFunction` + `func.apply(obj)`，文件体即构造器。
- 真正可用的热更新是游戏内 `update <路径>` → `BASE.UPDATE`；`os/util/hotload.js` 是废弃且会破坏数据的并行实现。
- 已确认 P0 缺陷 4 项（前端 eval 解析、hotload 空对象覆盖、GM `call` 远程 eval、票据含明文密码），P1 20 项，详见第 21 册。

## 新 MUD 技术选型（用户已确认三个输入变量）

用户目标：模仿 wushen 写一个新 MUD。确认变量：**AI 辅助开发** · **安全性最重要** · **在线规模 ≤ 200 人**。

**结论：TypeScript（Node 22+）+ 内容层 JS 脚本体（vm 沙箱隔离）+ zod 运行时校验。**

产出 `docs/wushen/23-技术选型与安全基线.md`，该文件是后续所有 AI 生成代码的约束契约。

### 推理要点（供后续会话直接引用）

- 「AI 开发」是权重最高的变量：AI 写代码最典型失败模式是**接口对不上**（A 处写 `room.name`、B 处读 `room.title`）。TS 类型 + `tsc --noEmit` 提供可喂回 AI 的反馈闭环；类型定义文件 = 给未来 AI 会话的持久契约。
- 诚实边界：**TS 只防自己人，防不住外部输入**（类型运行时擦除）。必须配 zod 做协议边界运行时校验。
- 「≤200 人」让性能彻底出局：单机单进程、全内存对象、SQLite 同步 API 即可；不引入 Redis/消息队列/多进程分片——复杂度本身就是安全风险。
- 「安全性最重要」指向**架构而非语言**：wushen 四层全破（明文票据、eval 解析、GM 远程 eval、内容脚本跑主上下文）。
- 关键洞察：TS 收益按层极不均匀——协议层/引擎层/前端层高，内容层（926 脚本体、字符串查表、原型篡改）几乎为零，而内容层占代码量 65%（39,086 行）。
- **内容脚本沙箱是本项目的特有风险点**：wushen 用 `vm.compileFunction` + `func.apply(obj)`，脚本体可访问全局（能 `require('fs')`）。要 AI 批量生成 926 个内容文件，出错概率高 → 必须改 `vm.runInNewContext` + 白名单 globals + `timeout: 1000`。
